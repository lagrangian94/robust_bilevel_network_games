# 비제로섬 α-B&B 분석과 개선 방향 (2026-10-08 ~ 10-10)

> **용어 (2026-10-13, 원고와 통일).** ϖˢ (리더 블록)·π̃ˢ (follower 블록) = **recourse 쌍대해** (원고: recourse dual solution, follower recourse 문제의 쌍대 실행가능해에 시나리오 가중치를 곱한 것). 그 예약 행 성분 t_s = Bᵀϖ_s = **subgradient** (원고: subgradient of the recourse function Q, −θᵁν_s 배). 이전 판의 "인증서" 와 원고 이전 판의 certificate·prices 가 이것이다. Lemma `certificate` (reaction set 의 certificate) 와 Farkas 인증서는 다른 대상이라 그대로 둔다.

zero-sum 에서 α-B&B (`true_dro/global_bilinear_solver.jl`) 는 Gurobi 전역보다 강했는데 (`docs/alpha_bnb_notes.md`: 루트 gap 3~6%,
S=50 에서 300 s 에 gap 0.07~0.26%), 비제로섬 (`nonzero_sum/nz_alpha_bnb.jl`, 기본 인스턴스 SGB128 + 예약 quota 150) 에서는
x = {1,2} 하나의 인증도 닫지 못했다. 원인 규명, 해결, 튜닝, 병목 측정, 다음 방향을 정리한다.
실험 표는 `experiments.md`, 원고 반영은 `paper/joc-non_zero_sum` (Lemma `lem:wd`, Remark `rem:theta-circuit`).

## 1. 원인: θ 벌점 항의 완화 오차

리더 블록은 F^L = ℓᵀŷ + θ(cᵀŷ − 쌍대목적) (pessimistic 평가의 정확 벌점). 정확한 점에서는 약쌍대성으로 θ 항 ≤ 0 (최적점에서 0).
완화에서는 primal 용량 (ζL = h^r·r) 과 쌍대목적 (ζW = h^r·ϖ) 이 따로 완화돼 **벌점이 보상으로 바뀐다**.
목적은 −158k (ŷ 항) 와 +190k (ϖ 항) 의 상쇄로 −1470 이 되는 구조라 오차가 θ × 비용 (마일) 으로 증폭된다.
zero-sum 은 θ = 0 (d_L = −d_F) 이라 이 항이 없고 곱의 상대가 확률이다.

증거 (`diag_box_width.jl`): 최적 α* 중심 폭 w 상자의 노드 상한 − V* 가 w 에 비례 (기울기 54.6/단위 폭) → 허용오차까지 활성 좌표마다 폭 ~0.003 필요.
분기 차원 (n_h = 15) 은 원인이 아님 (zero-sum 은 30~76).

| 해결 | 내용 | 효과 (x={1,2}, 600 s) |

## 6. 노드 완화 LP 의 구조 (OR 관점)

| 변수 묶음 | 크기 (S=200) | 등장 |
|---|---|---|
| 연결: h^r, belief (a,b,r,d,e,cpl), 곱 ζL·ζF·ζW, Z_a·Z_b·Z_e | ~80·S ≈ 16k | 시나리오 간 (Σ_s Z = h^r, TV 볼, CVaR, RLT) |
| 리더 블록 s: ŷ_s, ϖ_s, ρ̂_s | 65 / 시나리오 | 그 시나리오 행만 |
| follower 블록 s: ȳ_s, π̃_s, ρ̃_s | 65 / 시나리오 | 그 시나리오 행 + 집계 행 3 종 (follower 1 단계 KKT) |

- 연결 변수를 고정하면 리더 블록은 시나리오별 작은 LP 로 분리. 값은 (r_s, ζL_s, ζW_s) 에 대해 1 차 동차 → 절편 없는 선형 cut.
- follower 블록은 집계 행 (n_h + 1 + n_x 개) 으로만 묶임 → 집계량을 master 변수로 올리면 분리 가능.
- CVaR (β=0.4) 로 r 이 질량의 60% 이상에 퍼져 S=200 에서 활성 시나리오 120 개 이상 → 희소성 기법은 효과 작음 (실험과 일치).

**A. 노드 완화의 시나리오 분해 (L-shaped) + 전역 cut pool**
- master: 연결 변수 + 예약 행의 recourse 쌍대해 ϖ_H (상자 의존 RLT 행이 들어가는 변수). 블록: ŷ_s, 나머지 ϖ_s, ρ̂_s (흐름·쌍대 실행가능성·Wcap·WD 행).
- 이렇게 나누면 블록 LP 가 상자 K 와 무관 → cut (블록 값 ≤ gᵀ연결변수) 이 트리 전체에서 유효 → **전역 cut pool 에 누적, 노드 간 재사용**.
  상자 의존 행 (ζW − l·ϖ ≥ 0 등) 을 블록에 두면 cut 은 그 노드의 subtree 에서만 유효하므로 그렇게 나누지 않는다.
- 노드마다: 누적 cut 으로 master 를 warm start → 연결 변수를 고정해 시나리오 블록 LP (65 변수, 병렬) → 위반 cut 만 추가 → 반복.
  초반엔 라운드가 많아도 cut 이 쌓이면 새 노드는 몇 라운드면 수렴할 것으로 예상.
- 관리: cut pool 크기 (오래 tight 하지 않은 cut 은 pool 로 빼고 위반 시 다시), follower 블록은 2 단계 (집계량을 master 로).
- master 에 남는 곱 변수 (~80·S) 축소는 별도 과제.

**제외**: α-B&B 와 Gurobi 병렬 실행 (리뷰어가 싫어할 수 있음, 2026-10-10 결정).

**A 결과: L-shaped 노드 완화 통합 (`node_lp=:lshaped`, `logs/tune_abb_lshaped.log`, 600 s, ε=0.3, δ=0.1, x={1,2})**

**원인: 분해가 S 에 비례하는 층을 master 에 남김.** 블록 LP 를 상자와 무관하게 만들려고 상자 의존 RLT 행이 걸린 변수
(확률 a·b·r·d·e·cpl, 곱 ζL·ζF·ζW, ϖ_H, Z_a·Z_b·Z_e: ~80·S) 를 모두 master 에 두었다. 블록으로 빠진 것은 네트워크 흐름·쌍대 (65/시나리오) 뿐이라
LP 를 어렵게 만드는 확률·곱 층이 그대로 master 에 남았고, master LP 가 시간의 98%.

### 10.3.1 "실제로 최적이 될 수 있는 쌍대값 범위로 조인다" 를 풀어 쓰면

**쌍대값이 무엇인가.** 시나리오 s 의 recourse (follower 의 2 단계) 는 Q_s(α) = max{cᵀy : Ay ≤ ρ_s(α)} 이고 그 쌍대는
min{ρ_s(α)ᵀσ : Aᵀσ ≥ c, σ ≥ 0} 이다. 예약 행 k = (점포 i, 고객 j) 는 y^R_ij ≤ α_ij 이고, 그 쌍대값 σ_ks 는
"시나리오 s 에서 예약을 한 단위 더 해 두었다면 follower 비용이 얼마나 줄었는가" (예약의 한계가치) 다.
location 인스턴스에서는 예약분은 c_ij, 현장구매는 c_ij + p (p = 200) 이므로

| 시나리오 s 의 상황 | σ_ks |
|---|---|
| 수요가 예약보다 많다 (ξ_js > α_ij: 예약을 다 쓰고 현장구매까지 함) | p = 200 (한 단위 더 예약했으면 프리미엄을 아낌) |
| 수요가 예약보다 적다 (ξ_js < α_ij: 예약이 남음) | 0 |
| 딱 같다 (ξ_js = α_ij) | 0 ~ 200 사이 아무 값 (**꺾임점**) |

(용량이 묶이거나 더 싼 점포의 예약이 있으면 중간값도 나온다. 위 표는 가장 단순한 경우.)

**Ω 에서 이 값이 어디에 쓰이나.** Ω 의 recourse 쌍대해 변수가 바로 이 쌍대다: 리더 블록의 ϖ_ks = r_s σ_ks, follower 블록의 π̃_ks = d_s σ_ks.
비볼록 항 ζW = α_ij · ϖ_ks 가 여기서 나온다. 기존 완화는 σ 에 대해 **전역 범위 0 ≤ σ ≤ 200** (Wcap: ϖ ≤ p r) 만 알고 있어서,
α 와 ϖ 의 곱을 [0, 150] × [0, 200 r] 상자 위의 McCormick 으로 푼다 — 완화 오차의 대부분이 여기서 나온다.

**조인다는 것.** B&B 노드는 α 의 상자 B = [l, u] 다. 예를 들어 α_ij ∈ [100, 120] 인 노드를 보자.

| 시나리오의 수요 ξ_js | 상자 안 모든 α 에서 | 쓸 수 있는 범위 | 곱 ζW = α ϖ |
|---|---|---|---|
| 150 | 항상 예약을 다 씀 | σ = 200 으로 **고정** | ϖ = 200 r → ζW = 200·(α r) = 200 ζL: **선형, 정확** |
| 60 | 항상 예약이 남음 | σ = 0 으로 **고정** | ϖ = 0 → ζW = 0: **정확** |
| 110 (상자 안에 꺾임) | α 에 따라 다름 | [0, 200] 그대로 | 여전히 느슨 |

즉 "이 상자 안의 어떤 α 에서든 최적 쌍대가 될 수 있는 값" 만 남긴다. 꺾임점이 상자 밖에 있는 시나리오는 쌍대가 한 점으로 고정되고,
그 순간 그 시나리오의 subgradient 곱 (α × ϖ) 은 완화가 아니라 정확한 식이 된다. 상자가 작아질수록 꺾임을 품는 시나리오는 줄어든다
(S = 10, 폭 3 인 상자: 90 개 성분 중 83 개 고정). 느슨함이 "모든 시나리오" 에서 "꺾임이 상자 안에 있는 몇 개" 로 줄어드는 것이 효과의 전부다.

**범위는 어떻게 구하나.** 위 표처럼 수요와 상자를 비교하는 규칙은 쓰지 않는다 (용량·다른 점포 예약과 얽히면 틀림). 대신 시나리오 s 마다
작은 MIP 를 푼다: "α ∈ B 이고 (y, σ) 가 α 에서 시나리오 s recourse LP 의 최적 primal–dual 쌍 (상보성 조건을 이진변수로)" 을 만족하는 점 중
σ_k 의 최솟값과 최댓값. 변수 수십 개짜리라 한 개에 1~4 ms 이고, 부모 노드에서 이미 고정된 성분은 다시 풀지 않는다.
이 방식은 newsvendor 구조를 가정하지 않으므로 일반 LP recourse (`NZData`) 에 그대로 적용된다.

**노드 LP 에 들어가는 것.**
- 범위 행: σlo·r_s ≤ ϖ_ks ≤ σhi·r_s (리더 블록의 recourse 쌍대해), σlo·d_s ≤ π̃_ks ≤ σhi·d_s (follower 블록의 recourse 쌍대해).
- 이 행과 상자 인수의 곱 (RLT): (ϖ − σlo r)(α − l) ≥ 0 등 4 개. σlo = σhi 이면 ζW = σ ζL 로 떨어진다.

**왜 유효한가 (최적해를 잘라내지 않는가).** Ω 의 최적해에서 recourse 쌍대해는 **참 α 에서의** 최적 쌍대이고, 그 α 는 이 노드의 상자 안에 있다
(상자 밖이면 다른 노드가 담당). 따라서 "상자 안 어딘가에서 최적인 쌍대" 의 범위는 그 recourse 쌍대해를 반드시 포함한다. 줄어든 집합의 점은
여전히 Ω 의 점이므로 거기서 만든 Benders cut 도 유효하다. Wcap (ϖ ≤ p r) 이나 약쌍대 부등식 (WD) 과 같은 종류의 논증이다.
주의할 점 하나: α_ij = 0 (예약 안 함) 에서는 "한 단위 더" 의 가치가 [실제 한계가치, 200] 전체가 쌍대로 허용돼 범위가 부풀어 버린다.
이때는 더 낮출 수 없는 가장 작은 쌍대만 써도 최적성이 유지되므로 그렇게 제한한다 (이 제한이 없으면 효과가 거의 사라짐).

**나머지 세 강화는 같은 생각의 연장이다.**
- C (상자가 함의하는 상보성): 상자에서 α_i > 0 이 확실하면 follower 의 1 단계 최적성 조건 (newsvendor 식의 "한계가치의 기댓값 = 예약비")
  이 부등식이 아니라 **등식** 이다. 이 등식이 belief d 를 직접 묶는다.
- V (시나리오별 값 상한): 시나리오 s 의 리더 손실 φ_s(α) 가 상자 위에서 가질 수 있는 최댓값을 같은 MIP 로 구해 ℓᵀŷˢ ≤ φ̄_s r_s 로 막는다.
  쌍대가 고정되지 않은 (꺾임을 품은) 시나리오와 루트처럼 큰 상자에서 효과가 크다 (루트 상한 − V* : 730 → 329).
- X (상보성의 RLT): follower 의 상보성 조건 α_i × (1 단계 쌍대 여유) = 0 은 곱이라 그대로는 못 쓰지만, 곱 변수 (α κ, α π̃) 로 쓰면 선형 등식이 된다.
  10.2 에서 본 "F (α·d) 도 같이 조여야 한다" 에 해당하는 부분이다.

### 10.6 유효성과 수치 문제

**직접 검사** (`test_dr_validity_boxes.jl`): B&B 의 [LB, UB] ∋ V* 만으로는 약하다 (휴리스틱이 LB 를 V* 근처로 올리면, α* 를 품은 상자가
잘못 잘려도 UB ≥ LB 라 안 드러남). 그래서 독립 KKT 평가기의 최적 반응 α* 를 **품는 무작위 상자** 에서 노드 완화가 실행 가능하고 상한 ≥ V* 인지 본다.

| | 상자 | 상한 < V* | 재확인에서도 실행 불가능 |
|---|---|---|---|
| S = 3, x̄ ∈ {{1,2}, {1}, {2}, {1,2,3}}, 폭 ≥ 0.01, 변형 4 종 (W+F+C / +V / +X / 전부) | 1,600 | 0 | 0 |
| S = 5, x̄ = {2} (KKT 가 600 s 에 끝난 것만), 변형 2 종 | 120 | 0 | 0 |

**거짓 실행 불가능 판정.** 범위 행을 넣은 노드 LP 는 실행 가능한데도 INFEASIBLE 로 나오는 일이 있다 (위 검사에서 첫 판정 기준 0.5~1%,
범위 행이 없는 기존 완화는 400 개 중 0). 수학적 무효가 아니라 수치 문제라는 근거:
- 같은 상자를 새 모델에서 풀면 OPTIMAL.
- 제약이 더 많은 변형 (전부) 은 실행 가능한데 더 적은 변형 (X 만) 이 실행 불가능으로 나오는 경우가 있다 (제약을 빼서 실행 불가능해질 수는 없음).
- 점 상자 [α*, α*] 에서는 상한 = V*.

원인은 노드마다 행렬 계수를 바꾼 뒤 이어 푸는 dual simplex + `FeasibilityTol = 1e-9` (build_nz_omega 의 설정). FeasibilityTol 만 1e-6 으로
풀고 이어 풀면 그대로 실행 불가능이고, **기저를 버리고 (GRBreset) primal simplex 로 1e-6 에서 처음부터** 풀면 풀린다
(`_nz_dr_recheck_infeasible!`). 지금은 INFEASIBLE 판정마다 이 재확인을 거친 뒤에만 가지치기한다. 최종 측정에서 재확인으로 되살아난 노드:
S = 3 에서 463 개 중 89, S = 20 에서 43 개 중 8.

**남은 것**
- 재확인을 통과한 "실행 불가능" 이 전부 진짜인지는 증명하지 못했다 (검사에서는 α* 를 품은 상자 1,720 개 중 0). 근본 대책은 계수를 바꾸지 않는
  정식화이거나 실행 불가능 판정을 Farkas 인증서로 검증하는 것.
- 범위 MIP 의 `Gurobi Error 10005` (worker 12 개 첫 실행에서 worker 전멸, `logs/scale_oracle_dr2_failed_S3.log`): 이후 실행에서는 0 회, 원인 미확인.
  한 번 재시도 후 실패하면 그 성분을 부모 범위로 두고 (유효) 횟수를 `:range_fail` 로 보고한다.
- `F` (π̃ 범위) 는 "H 행 성분이 ϖᵁ 이하이고 더 낮출 수 없는" 2 단계 LP 최적 쌍대의 존재를 쓴다. location 에서는 성립하지만
  (τ = (μ − κ − c d)⁺ ≤ p d) 일반 `NZData` 에서는 가정이다.
- Benders 와는 10.7 에서 연결했다. 탐색 루프는 여전히 새 파일에 복사한 상태 (`nz_alpha_bnb.jl` 과 합치지 않음).

oracle 은 상한 −987.28 ≤ target −986.01 에서 "증명 끝" 으로 멈추는데, 그 상한으로는 gap 이 0.53% 라 Benders 는 수렴으로 보지 않는다.
incumbent 의 cut 은 이미 들어 있어 LB 도 안 움직이므로 같은 x̄ 에서 같은 호출 (80~90 s) 이 시간 제한까지 반복됐다.
**수정 (2026-10-11)**: target = t₀ + 0.99·tol·max(1, |LB|) / (1 + tol). oracle 상한 zbd ≤ t₀ + δ 이면 UB ≤ LB + δ, |UB| ≥ |LB| − δ 이므로
δ = 0.99·tol·|LB| / (1 + tol) 이면 δ ≤ tol·|UB| 가 보장된다. 수정 후 재측정 (`logs/loc_base_scaling_dr_S20_targetfix.log`): 위 표의 두 행.

**읽는 법.** Algorithm 2 에서는 S = 20 에서 기존 α-B&B 와 새 α-B&B 의 차이가 없다 (195 s vs 186 s). belief cut 이 x = {1,2} 를 oracle 없이
배제해서 oracle 이 인증해야 하는 것은 쉬운 x = {1} 뿐이기 때문이다 (기존 111 s, 새 54 s). 새 α-B&B 가 결정적인 곳은 어려운 x̄ 를 인증해야 하는
SB-A (TimeLimit → 479 s) 다. Algorithm 2 도 최적 x̄ 자체의 인증이 어려우면 같은 차이가 날 것이다 (x = {1,2} 의 oracle 만 보면 S = 30 에서
600 s 에 9.3% vs 1.1%). 다만 S = 30 에서 어느 x̄ 가 최적인지, Algorithm 2 가 그 인증을 요구하는지는 아직 재지 않았다.

### 10.11 꺾임 정보를 쓰는 두 시험: 분할 위치, 계단 cut (2026-10-12, 둘 다 채택 안 함)

10.10 의 후보 1 을 시험했다. oracle 단독, S = 20, x̄ = {1,2}, worker 12, 목표 gap 1e-3, 600 s. 기준은 기본 구성 (중점 분할) 의 10.10 실행.

**(a) 꺾임 사이 분할** (`branch_point=:kinkmid`, 커밋 b3775b2 의 `_nz_dr_kinkpts`·`_nz_kink_split`).
분기 좌표 i 가 정해지면, 그 좌표의 고정 안 된 성분 (k, s) 마다 범위 MIP 두 개로
p⁺ = max{α_i : σ_k 가 아직 hi 일 수 있음}, p⁻ = min{α_i : σ_k 가 이미 lo 일 수 있음} 을 구해 상자 안 꺾임 위치로 삼고,
꺾임 수가 절반씩 되도록 가운데 두 꺾임의 중간에서 나눈다 (1 개면 넓은 쪽 틈의 가운데, 0 개면 중점. 경계 5% 안쪽으로 자름).

**(b) 계단 cut** (`stepcut`, 커밋 a686019 의 `_nz_dr_steps`). 꺾임 위치를 분할이 아니라 완화에 넣는다.
P = p⁺ + η 에서 좌표 i 를 나눈 오른쪽 자식의 범위 hiR = max{σ_k : α ∈ B, α_i ≥ P} 를 미리 구하면 B 에서
σ_k ≤ hi (α_i < P), σ_k ≤ hiR (α_i ≥ P) 이고, 이 계단의 오목 포락선 σ_k ≤ hi − (hi − hiR)(α_i − P)/(u_i − P) 가 유효하다
(아래쪽도 대칭). r_s 를 곱하면 ϖ, r, ζL 의 선형 행 (follower 쪽은 π̃, d, ζF). 유효성은 자식 상자 범위의 정의에서만 나온다.
S = 3 의 α* 를 품은 무작위 상자 300 개 (cut 1,293 개) 에서 상한 < V* 0 건 (`logs/test_dr_validity_boxes_step_S3.log`).

#### (1) worker 병렬의 GC 대기 (`gurobi_gcsafe.jl`)

Julia 의 GC 는 stop-the-world 라 한 스레드가 GC 를 시작하면 모든 스레드가 safepoint 에 닿을 때까지 기다리는데, **ccall 안의 스레드는
safepoint 가 아니다.** worker 하나가 Gurobi LP 를 푸는 동안에는 GC 가 시작되지 못하고, 그 사이 LP 를 끝낸 다른 worker 는 메모리 할당
지점에서 멈춘다. worker 12 개가 번갈아 LP 를 풀면 이 대기가 겹친다.

| 120 s 실행 (tol 1e-7 + FWD) | 노드 | safepoint 대기 (`Base.gc_num().total_time_to_safepoint`) | GC 자체 |
|---|---|---|---|
| 그대로 | 373 | 82.0 s | 1.1 s |
| Ipopt 휴리스틱 끔 | 479 | 80.0 s | 1.0 s |
| GRBoptimize 를 GC-safe 구간에서 | 860 | 0.3 s | 2.6 s |

wall 120 s 중 82 s 동안 전체가 멈춰 있었다 — worker 12 개가 4 개 남짓으로 돈 셈이다. 10.10 의 "worker 유휴 20~28%",
8 절의 "worker 12 개 동시 barrier 는 경쟁으로 LP 1 회 3.4 → 13.8 s", "worker 6 이 처리량 거의 같음" 은 이것으로 설명된다 (그때는 메모리 경쟁으로 봤다).
`gurobi_gcsafe.jl` 은 Gurobi 모듈의 `GRBoptimize` 를 `jl_gc_safe_enter` / `jl_gc_safe_leave` 사이에서 부르도록 덮어쓴다
(Julia 1.12 의 `@ccall gc_safe=true` 와 같은 일). `nz_alpha_bnb_dr.jl` 이 include 하고 `NZ_GCSAFE=0` 으로 끈다. 결과 Dict 의 `:gc_wait`.
**이 패치 전의 α-B&B 시간·노드 수 (10.12 까지 전부) 는 패치 후와 직접 비교할 수 없다.** 기존 구현 `nz_alpha_bnb` 도 같은 프로세스에서는 혜택을 받는다.

#### (2) 노드 LP: 허용오차와 행 관리

- **허용오차** (`lp_tol = 1e-7`). `build_nz_omega` 는 θ 항의 상쇄 때문에 FeasibilityTol = OptimalityTol = 1e-9, NumericFocus 2 로 둔다
  (θᵁ = 1200 이던 때의 설정). 같은 상자 66 개에서 1e-7 + NumericFocus 0 은 상자당 LP 5.14 s → 0.69 s 이고 가지치기되는 상자 수는 같다 (20 → 21).
  NumericFocus 만 0 으로 하면 3.99 s 라 원인은 허용오차다. 덜 수렴한 목적값을 상한으로 쓰는 것에 대비해 노드 상한에 상대 1e-6 을 더한다.
- **분리 행 제자리 갱신** (`sticky`). 기존 방식은 상자 경계가 다른 RLT 행을 새로 쌓고 안 맞는 행은 rhs = −∞ 로 꺼 둔다. worker 의 LP 가
  계속 커지고 (10.12: 30 분에 분리 행 2 만 개, 처리량 1/3), 자식 노드에는 부모 경계의 느슨한 행만 남아 분리 라운드를 더 돌아야 조여진다
  (같은 상자에서 라운드 1 → 30 이면 가지치기 21 → 31 개, 그러나 `child_rounds = 4` 는 LP 횟수 때문에 시간으로는 손해: 0.39% → 0.59%).
  제자리 갱신은 (좌표 i, 후보 행 j, 쪽) 마다 LP 행을 하나만 두고 상자가 바뀌면 경계 b 를 지금 상자의 l_i (u_i) 로 바꾼다.
  LP 크기가 묶이고 노드에 들어설 때 모든 행이 이미 지금 상자 기준이다. 10 분 처리 노드 2,884 → 7,895, gap 0.27% → 0.11%.
  10.12 의 "처리량이 시간에 따라 1/3 로 준다" 의 원인은 쌓인 행이었다.

#### (3) follower 블록 완화에 빠져 있던 것

`lab_blame.jl`·`lab_inspect.jl` 로 정체한 상자의 노드 LP 해를 뜯어 보면, **리더 블록은 정확하다** (Σ_s r̂_s φ_s(α̂) = 노드 상한, 시나리오별 α 도 α̂ 와 같음).
상한이 LB 보다 높은 것은 α̂ 가 리더에게 유리한 점인데 **어떤 belief 로도 follower 최적이 아니어서** 다 (α̂ 고정 정확 LP 는 벌점 수천).
즉 남은 오차는 전부 follower 최적성 (F) 쪽이고, 다음 셋이 그것을 막는다.

| 이름 | 내용 | 왜 빠져 있었나 |
|---|---|---|
| FWD | 시나리오별 약쌍대 cᵀȳˢ ≤ (uˢ + gˢx̄)ᵀπ̃ˢ + Σ_{k∈H} hcoef_k ζΠ_ks | Flam (합친 강쌍대) + X 의 항등식은 Σ_s [쌍대목적_s − primal_s] ≤ 0 만 준다. 꺾임을 품은 상자에서는 시나리오끼리 부호가 다른 gap 을 상쇄한다. 리더 블록에는 같은 행 (WD) 이 있었고 follower 블록에는 곱 변수 ζΠ 가 X 와 함께 뒤늦게 생겨서 없었다 |
| 상보성 분기 | l_i = 0 인 좌표에서 α̂_i > 0 이고 정상성 여유 ĝ_i > 0 이면 {α_i = 0} \| {g_i = 0, 상자 그대로} 로 분기 | C 는 l_i > 0 일 때만 정상성을 등식으로 둔다. 중점 분할의 왼쪽 자식 [0, u/2] 에는 완화된 상보성 (α_i ≤ u_i (1 − g_i / gmax)) 이 그대로 남아 오차가 폭에 비례해 반씩만 준다 — 10.2 의 "기울기 ~5 / 단위 폭" 의 한 출처 |
| DD | 쌍대 **차이** 의 범위 dlo ≤ σ_k − σ_k′ ≤ dhi (같은 KKT-MIP, 목적만 σ_k − σ_k′). dlo d_s ≤ π̃_ks − π̃_k′s ≤ dhi d_s, 리더는 ϖ 와 r_s | 성분별 범위 [lo, hi] 는 곱집합이라 두 쌍대가 함께 움직이는 것을 놓친다 |

DD 가 잡는 것의 예 (정체한 상자 하나, `lab_inspect.jl`): 고객 3 은 B1 (수송비 217) 과 A (258) 에 예약할 수 있다. 수요가 두 예약의 합을 넘는 시나리오에서
두 예약의 한계가치는 (200, 159), 그 아래에서는 (41, 0) 이라 **차이는 늘 41** 이다. 성분별 범위는 [41, 200] × [0, 159] 라 LP 는 (41, 62) 를 고른다.
차이가 41 로 묶이면 두 좌표의 정상성 Σ_s π̃ = f + κ 가 동시에 등식일 수 없고 (B1 한도가 남는 한), 따라서 A 예약 α_3 > 0 인 자식은 바로 실행 불가능이 된다.
이것은 "더 싼 점포의 한도가 남아 있으면 비싼 점포에 예약하지 않는다" 는 지배 관계인데, 인스턴스 구조를 쓰지 않고 범위 MIP 가 찾아낸다.
노드당 범위 MIP 는 37 → 69 개 (노드당 0.17 s) 로 늘고 노드 수는 6,012 → 588 로 준다.

KMC (κ_l ≤ κmax_l = max_i (Σ_k hcoef_k ϖᵁ_k + c0_i) / W_li 와 Zκ = α κ 의 위쪽 McCormick) 는 상자가 넓고 α̂_i = 0 인 좌표에서
Zκ_il 이 u_i κ_l 까지 자유로워 한도 상보성 κ_l (w_l − W_l α) = 0 의 선형화가 비는 것을 막는다. 같은 상자 묶음에서는 효과가 작았고 (가지치기 40 → 41) 상보성 분기와 함께 넣었다.

#### (4) 실행 불가능 재확인의 비용 (`lab_recheck.jl`)

노드 LP 가 INFEASIBLE 이면 10.6 의 거짓 판정 때문에 기저를 버리고 처음부터 다시 푼다. 새 구성에서는 노드의 12~14% 가 이 재확인을 거치는데,
그 시간은 `t_relax` 에 잡히지 않아 보이지 않았다 (DD 를 넣은 실행에서 worker 시간의 3 분의 2 가 "완화 LP 도 범위 MIP 도 아닌" 시간).
S = 20 의 첫 판정이 INFEASIBLE 인 상자 40 개에서 처음부터 푸는 방법을 비교했다 (노드 LP 자체는 0.23 s).

| 방법 | 평균 | 최대 | 실행 불가능 확정 / 되살아남 |
|---|---|---|---|
| A: primal simplex, Presolve 끔 (지금까지) | 8.37 s | 36.9 s | 35 / 5 |
| B: dual simplex, Presolve 켬 | 0.06 s | 0.18 s | 40 / 0 |
| C: primal simplex, Presolve 켬 | 0.48 s | 0.83 s | 40 / 0 |
| D: dual simplex, Presolve 끔 | 0.32 s | 1.37 s | 40 / 0 |

A 가 되살린 5 개는 목적값이 LB + 10⁶ ~ 6·10⁷ 인 쓰레기 해다 (나머지 셋은 모두 실행 불가능). 그 노드들은 부모 상한을 물려받아 다시 나뉘기만 했다
(이전 실행들의 "재확인에서 되살아남" 의 대부분이 이것으로 보인다: 1 시간 실행에서 47 개, DD 실행에서 10 개 → 바꾼 뒤 1 개).
**B 로 바꾸고, B 가 실행 불가능이라고 하면 D 로 한 번 더 확인해 둘 다 실행 불가능일 때만 가지치기한다.**
참으로 실행 가능한 상자를 이 재확인이 실행 불가능으로 보지 않는지는 강제 재확인으로 봤다 (`TV_FORCE_RECHECK=1`: α* 를 품은 모든 상자에서
재확인 함수를 직접 부름): S = 3 의 seed 1·2·3 × x̄ 4 개 × 250 상자 = 3,000 개와 S = 20 의 incumbent 상자 150 개에서 0 건, 첫 판정이 거짓 INFEASIBLE 이던
19 개는 모두 되살아남 (`logs/test_dr_validity_boxes_recheck_seed*_S3.log`, `logs/test_dr_validity_incumbent_recheck_seed3_S20.log`).
seed 3 의 oracle 136 → 94 s, seed 2 (S = 30) 의 oracle 808 → 522 s.

노드 LP 의 수치 오류 재시도 (`_nz_solve_lp!`) 도 같은 식으로 바꿨다: NumericFocus 3 으로 가기 전에 기저를 버리고 Presolve 를 켠 dual simplex 로
한 번 푼다 (`model.ext[:retry_fresh]`, 기존 구현 `nz_alpha_bnb` 에서는 꺼져 있음). seed 2 (S = 30): 수치 오류 23 건 중 22 건이 이것으로 풀리고 실패 4 → 0,
522 → 446 s (`logs/scale_oracle_v4b_seed2_S30.log`). 그래도 LP 한 번에 40~90 s 걸리는 노드가 몇 개 남는다 (결과 Dict 의 `:slow_nodes`) — 원인 미확인.

3. 같은 인스턴스는 10-08 의 파일럿에서도 풀리지 않았다 (`logs/pilot_loc_random_d15.log`: KKT 전수 평가가 x 당 300 s 제한에 걸림). 즉 10.13 의 개선은
   **분기 차원이 작을 때 (활성 좌표 10 안팎) 의 시나리오 수 확장** 에 대한 것이고, 분기 차원 확장은 아직 열려 있다.

### 10.15 왜 루트 상한이 0 인가, 무엇이 막는가 (2026-10-13~14, `diag_root_gap.jl`, `diag_resp_cells.jl`)

10.14 의 인스턴스 (무작위 pair, d = 15, n_h = 50, 활성 30, S = 3, seed 1, x̄ = {1}) 에서 원인을 하나씩 갈랐다. incumbent 는 α-B&B 의 −1300.2464.
로그: `logs/diag_root_gap_d15_seed1_S3_x1_CE.log` (C, E), `…_G.log` (G), 나머지는 아래 표에 옮겨 적음.

**(1) θᵁ 벌점은 원인이 아니다.** θᵁ 를 50 → 20 → 5 로 줄여도 (유효성 보장 없는 민감도 확인) 루트와 α° 둘레 상자의 상한이 소수 둘째 자리까지 같다.

**(2) 루트 완화의 해가 하는 일.** 리더 블록의 B 판매량이 0 이다 (follower 블록은 173~250, 같은 α̂ 에서의 참값은 187~214). 리더 블록의 시나리오별 예약
ζL/r 이 공통 α̂ 에서 좌표 합으로 200~440 벗어난다: 완화에서는 시나리오마다 다른 예약을 쓰는 (wait-and-see) recourse 가 허용되고, ζW = α·ϖ 가 풀려 있어
"리더 복사본이 recourse 최적" 이라는 조건이 걸리지 않는다. belief 를 incumbent 값에 고정해도 (d 만, (a, r) 만, 전부) 루트 상한은 0 그대로다 —
belief 쪽 곱이 정확해져도 α 가 넓으면 ζW 가 풀려 있기 때문이다.

**(3) 상한은 상자 폭에 1 차로만 줄어든다.** α° 를 중심으로 폭 f × hᵁ 인 상자 (f = 1 은 α° ± hᵁ/2 로 루트보다 작다) 의 gap = (상한 − LB)/|LB|:

| f | 1 | 0.5 | 0.25 | 0.125 | 0.06 | 0.03 | 0.015 |
|---|---|---|---|---|---|---|---|
| RLT 만 | 100% | 100% | 66.8% | 38.0% | 16.4% | 8.1% | 4.0% |
| 쌍대 범위 | 100% | 75.0% | 38.2% | 22.3% | 8.9% | 4.5% | 2.2% |
| + 차이 범위 (기본) | 100% | 75.0% | 38.2% | 22.3% | 8.9% | 4.5% | 2.2% |
| 쌍대 고정 비율 | 0.28 | 0.29 | 0.40 | 0.50 | 0.68 | 0.79 | 0.82 |

폭을 반으로 줄이면 gap 도 반이 된다. 0.1% 까지 가려면 f ≈ 0.0007 (예약 0.2 단위) 이어야 하는데 자유 좌표가 20 개가 넘는다 — 상자 수가 감당이 안 된다.
최적 반응 α° 가 Q_s 의 꺾임 위에 있어 (follower 의 최적 반응은 LP 꼭짓점이라 늘 그렇다) α° 를 품은 상자는 아무리 작아도 쌍대가 고정되지 않는다 (0.82 에서 멈춤).
**차이 범위 (DD) 는 이 인스턴스에서 상한을 전혀 바꾸지 않는다** (모든 폭에서 쌍대 범위만 쓴 값과 같음) — 범위 MIP 시간만 10 배 (루트 2.7 s → 28 s).
따라서 10.14 에서 후보로 적은 "DD 쌍을 같은 고객의 점포끼리로 제한" 은 비용만 줄일 뿐 상한에는 도움이 안 된다.

**(4) 싸게 줄일 수 있는 것 두 가지 (둘 다 유효, 둘 다 결론을 바꾸지는 못함).**
- 예약 상한을 고객의 최대 수요로: h_ij > max_s ξ_j^s 인 예약은 어느 시나리오에서도 쓰이지 않고 예약비 f > 0 만 내므로 모든 belief 에서 최적 반응이 될 수 없다
  (`nz_presolve_hU` 와 같은 종류의 지배 논증). 이 인스턴스는 할당량 300 대 수요 ≤ 149 라 Σhᵁ 9,000 → 3,987. α-B&B 300 s: RLT 만 44% → 38%, 쌍대 범위 75% → 71%
  (`logs/scale_oracle_random_seed1_S3_x1_hudem_*.log`). 루트 상한은 여전히 0. 기본 인스턴스 (할당량 150, 수요 30~240) 에서는 거의 해당 없음.
- 노드 LP 위의 범위 조임 (목적 ≥ LB 인 영역에서 좌표별 min/max α_i, LP 60 개): 루트에서 한 라운드에 α 폭 합 100% → 33%, 좌표 8 개가 0 으로 고정 (자유 30 → 22),
  상한 0 → −96. 둘째 라운드부터는 멈춘다 (33% → 30%). α° 둘레 상자에서도 폭을 1/4 쯤 줄이고 끝난다.

**(5) belief 쪽에서 보면 S = 3 은 작은 문제다.** follower 의 2 단계 LP 는 d 가 목적에만 들어가므로 최적 반응 α*(d) 는 d 의 조각별 상수 (LP 꼭짓점) 다.
TV 볼의 d 를 훑어 서로 다른 α*(d) 를 모으고 α 고정 LP 로 값을 구하면 (`diag_resp_cells.jl`):

| 인스턴스 | S | belief 표본 | 서로 다른 최적 반응 | 그중 최댓값 | 시간 |
|---|---|---|---|---|---|
| 무작위 n_h = 50, x̄ = {1} | 3 | 격자 2,700 (간격 0.01) | **26** | **−1300.1667** (α-B&B incumbent −1300.2464 이상) | 2.6 s |
| 〃 | 5 | 무작위 20,020 | 912 이상 | −1155.86 | 25 s |
| 〃 | 10 | 무작위 20,090 | 13,179 이상 (표본 대부분이 서로 다름) | −1014.85 | 376 s |
| SGB128 n_h = 15, x̄ = {1,2}, seed 2 | 30 | 무작위 3,870 | 526 | −1278.20 (최적은 약 −1266: 0.8~1.0% 모자람) | 37 s |

같은 x̄ 에서 KKT 재정식화를 Gurobi 로 풀면 (`nz_kkt_value`, `nz_kkt_value_reduced`, 10 스레드, 240 s) 둘 다 실행가능해를 하나도 못 찾는다.
즉 S = 3, n_h = 50 은 α 공간 (30 차원) 에서는 못 닫지만 belief 공간 (2 차원) 에서는 반응이 26 가지뿐이다. 반대로 S 가 10 만 되어도 반응의 수가 폭발하고,
S = 30 의 기본 인스턴스에서는 무작위 belief 표본이 최적 반응을 못 맞힌다 (primal 휴리스틱으로도 부족).
주의: 위 최댓값은 증명이 아니다 — 표본이 놓친 셀이 있을 수 있고, 셀 경계에서는 최적 반응이 면 전체라 그 내부 점의 값이 꼭짓점 값보다 클 수 있다
(φ_s 는 Q_s 의 선형 구간에서 α 에 오목하다). 정확한 방법으로 만들려면 경계의 면을 따로 다뤄야 한다.

**(6) d 를 분기해 완화로 α 를 묶는 방식은 느리다.** d 를 셀 무게중심 둘레 폭 w 로 묶고 (4) 의 범위 조임을 반복하면 α 상자가 줄지만, w = 0.02 에서도 라운드마다
폭이 0.6 배쯤으로만 줄어 4 라운드 뒤 gap 4.9~13.4%, α 폭 3~7.5% (라운드 하나에 4~5 s). (d 상자의 최적 반응 범위를 KKT-MIP 로 직접 구하는 시험 (E) 은
indicator 정식화의 MIP 60 개가 모두 20 s 제한에 걸려 정보를 주지 못했다.) belief 쪽으로 가려면 완화가 아니라 LP 민감도 (기저가 유지되는 d 의 다면체) 로 셀을 세는 쪽이 맞다.

정리.
- 분기 차원 (자유 예약 좌표) 이 20 을 넘으면 α-B&B 는 닫지 못한다. 원인은 벌점 상수가 아니라 **꺾임 위의 최적 반응 둘레에서 완화 오차가 상자 폭에 1 차** 라는 것과 차원이다.
  기본 인스턴스 (활성 9) 에서 통한 조임 (쌍대 범위, DD, 상보성 분기) 은 그 오차를 없애지 못하고, DD 는 여기서 효과가 0 이다.
- 풀리는 영역은 두 쪽이다: 반응 차원이 작고 S 가 큰 쪽 (α-B&B, 지금의 실험) 과, S 가 아주 작고 (3~5) 반응 차원이 큰 쪽 (belief 쪽에서 반응을 세는 방법, 아직 없음).
  둘 다 큰 경우 (n_h = 50, S ≥ 10) 는 어느 쪽으로도 안 된다.
- **구분 (2026-10-14 보충): 위의 "반응의 수" 는 상한 증명을 열거로 하려 할 때의 크기이지, belief cut 에 필요한 belief 의 수가 아니다.** 하한 쪽은 이 인스턴스에서도 기대대로다:
  10.14 의 Benders 실행 (`logs/pilot_loc_random_v4_pair_S3.log`) 은 belief 6 개로 1 분 안에 LB = −550.1667 = 750 − 1300.1667 (출점비 + 위 격자의 최댓값) 에 닿았고,
  나머지 1,742 s 는 x̄ = {1} 의 인증 호출 하나였다 (상한 −312.87). 막히는 것은 "어느 belief 에서도 더 나쁜 반응이 없다" 는 증명 하나뿐이다.

### 10.16 반응 정의역 프리솔브 (2026-10-14, 시제품) — 루트 LP 로 최적 반응이 될 수 없는 예약 좌표를 0 으로 고정

10.15 의 진단 중에 나온 부수 결과. **기본 인스턴스의 벤치마크가 빨라진다.** 솔버 (`nz_alpha_bnb_dr`) 에는 아직 연결하지 않았다 (사용자 확인 대기).

**방법** (`nz_root_tighten.jl` 의 `nz_response_presolve`). 루트 노드 LP (기본 구성의 조임 전부, RLT 분리까지) 에서 좌표마다 max α_i 를 풀어, 값이 0 인 좌표의
예약 상한을 0 으로 둔다. LP 는 활성 좌표 수만큼, incumbent 는 필요 없다 (목적 조건을 쓰지 않는 실행가능성 기반 조임). S = 20 에서 5~7 s, S = 50 에서 14~23 s.

**유효성.** 루트 노드 LP 는 Ω 의 완화에 "최적값을 바꾸지 않는 제한" (루트 상자의 쌍대 범위·차이 범위 등) 을 더한 것이고, 그 제한들은 쌍대의 선택만 줄인다:
모든 belief 의 모든 최적 반응 α 에서 그 제한을 만족하는 완성이 있다 (10.3, 10.13 의 논증). 따라서 Ψ(x̄, 𝔅) 는 LP 실행가능 영역의 α 사영 안에 있고, 사영 밖을 버려도
V*(x̄) 는 그대로다. 0 으로 고정되는 것은 "쌍대 범위의 상한으로도 예약의 한계 가치 Σ_s d_s σ_ks 가 예약비에 못 미치는" 좌표다 — 정상성 여유가 양수라 상보성의 RLT 가
α_i = 0 을 강제한다. 원고 4.3 의 성질 (i) (국소화된 subgradient) 을 루트 상자에 쓴 귀결이다.

**(2) 오차의 분해** (`diag_root_gap.jl` 의 H, 루트 α 상자의 gap). zero-sum 에 없고 비제로섬에 있는 것은 두 가지다.
- (i) 리더 복사본의 recourse 최적성 cᵀŷ_s ≥ Q_s(α). Q_s 는 α 에 오목한 조각별 선형이라 이 조건은 **역볼록** 이다 (조각 = recourse 쌍대 꼭짓점 σ 마다
  cᵀŷ ≥ L_σ(α) 의 합집합). Ω 에서는 −θ(…+ α·ϖ) 로 들어가고 McCormick 오차가 α 폭에 1 차다. zero-sum 은 θ = 0 이라 이 항이 없다.
- (ii) follower 의 1 단계 최적성 α ∈ Ψ(d). Ω 는 primal 을 d 로 스케일해 곱 α·d 로 쓰는데, 완화에서는 시나리오마다 다른 예약 (wait-and-see) 이 허용된다.

| 루트 α 상자에서 고정한 것 | gap |
|---|---|
| 없음 (쌍대 범위만) | 100% |
| belief 전부 (d°, a°, r°) | 100% |
| 리더 쌍대 조각 σ° (세 시나리오) | 39.6% |
| 조각 + d° | 12.2% |
| 조각 + (a°, r°) | 23.0% |
| 조각 + belief 전부 | **0.01%** |
| 조각 + "α 가 그 조각의 선형 구간 안" (스케일 없는 복사본 y^u ∈ Y_s(α), cᵀy^u ≥ L_σ°(α)) | 18~20% |
| 〃 + 노드 LP 위의 범위 조임 한 라운드 (LP 60 개) | **0.4%** (α 폭 합 100% → 7.4%) |

즉 오차는 (i) 조각과 (ii)·α × belief 곱이 전부이고, 조각이 정해진 영역 안에서는 완화가 스스로 α 를 조인다. 그러나 조각으로 나누는 분기 (쌍대 쪽 분기) 는
꺾임 위의 최적 반응 둘레에서 조각의 조합이 2^(꺾임 수) 로 늘어 α 분기와 같은 문제를 다른 모양으로 만난다 — 구현하지 않았다. 옛 구현의 ϖ 분기는 변수 ϖ = rσ 의
이등분이라 조각을 고르는 것이 아니고, 위 표대로 효과가 없다.

**(3) 구조: 최적 반응의 집합은 차원 min(n_h, S − 1) 이하.** follower 의 2 단계 LP 는 실행가능 집합이 d 와 무관하고 d 는 목적에만 들어간다. 따라서 Ψ(x̄, d) 는
d 의 조각별 상수 (LP 의 최적면) 이고, belief 볼 위의 최적 반응 전체는 d 로 매개되는 다면체 복합체다 — 차원이 S − 1 을 넘지 않는다.

**(4) belief 공간 셀 열거 oracle (`nz_belief_cells.jl`, S = 3 시제품).**

- (2) 의 "조각을 고정해도 남는 39.6%" 는 follower 블록의 완화가 그 자체로 나빠서가 아니다 (대조군에서는 같은 완화가 1.3% 다). 리더의 목적이 follower 와 어긋날 때만
  완화가 허용하는 follower 최적이 아닌 α 가 리더 값에 이득이 된다.
- ϖ 를 "추가로 분기" 하는 것은 답이 아니었다: 지금은 α 만 분기하고 ϖ 는 상자별 범위로 묶는데, 옛 구현의 ϖ 분기는 (1) 대로 효과가 없다. ϖ 가 있으면 α 분기의 효율이 떨어지는 것이고,
  그 손해를 차원이 작을 때 (활성 9) 는 감당하고 클 때 (활성 30) 는 못 한다.

정리. α-B&B 를 n_h 에 스케일하게 고치는 길은 찾지 못했다. 원인은 구현이나 차원 자체가 아니라 리더 블록의 α·ϖ 곱 ((i) 의 역볼록성) 이고, 그 항이 없으면 같은 인스턴스가 닫힌다 ((7)).
n_h 가 큰 비제로섬 인스턴스에서도 Benders 의 belief cut 은 몇 개면 최적값에 닿는다 (10.15 보충). 남은 것은 x̄ 하나에서 상한을 닫는 계산뿐이다.
(4) 의 belief 셀 열거는 그 계산을 S = 3 에서 대신해 본 시도 중 하나로, 지시받은 방향이 아니고 S 가 커지면 쓸 수 없어 결론에서 뺀다.

### 10.18 전역 솔버의 bilinear 처리에 비춰 다시 보기 (2026-10-14) — 고정 x̄ 에서는 α·ϖ 곱을 정식화로 피할 수 있다 (S = 3 은 Gurobi 가 닫음, S ≥ 5 는 아직)

질문: 기존 spatial B&B·전역 솔버 (BARON 등) 는 bilinear 를 어떻게 다루는가, 그 도구로 α·ϖ 병목을 풀 수 있는가, 안 되면 Gurobi 나 다른 전역 솔버에 우리 발견을 얹는 쪽은 어떤가.
대상은 10.14 의 인스턴스 (무작위 pair, d = 15, n_h = 50, seed 1, x̄ = {1}), **프리솔브는 모두 켬** (닫힌 점포 + 예약 상한 ≤ 최대 수요 + 10.16 의 반응 정의역 프리솔브: 활성 30 → 22).
스크립트 `nonzero_sum/lab_vf_form.jl` (새 파일), 로그 `nonzero_sum/logs/lab_vf_form_*.log`.

**(1) 전역 솔버의 도구와 우리 쪽 대응**

| 도구 (대표 출처) | 하는 일 | 우리 쪽 |
|---|---|---|
| McCormick + 공간 분기 | 곱 w = xy 의 포락, 오차 ≤ (x 폭)(y 폭)/4 | α-B&B 의 기본 |
| RLT (Sherali–Adams; SCIP·Gurobi 의 RLT cut) | 제약 × bound factor. 한 변수 × 다면체는 정확한 볼록포 | 있음 (α 상자 × belief 다면체). full RLT 는 이득 2 배 |
| 범위 축소 = BARON 의 "branch-and-reduce" (Ryoo–Sahinidis; Puranik–Sahinidis 2017) | FBBT, OBBT, 한계값 (reduced cost) 기반 조임, probing 을 노드마다 | 쌍대 범위 MIP (OBBT 의 강한 판), 반응 정의역 프리솔브 (루트 OBBT). 노드 LP 위의 α 범위 조임은 한 라운드만 효과 (10.15) |
| 여러 곱을 묶은 볼록화 (Bao–Sahinidis–Tawarmalani 2009; Tawarmalani–Richard–Xiong 2013) | 곱의 합의 포락을 꼭짓점으로 | 꼭짓점 포락 시험 (10.5): 같은 상한, 훨씬 비쌈 |
| 분기 변수 선택 | 곱의 한쪽만 분기해도 수렴 → 변수가 적은 쪽을 고른다 | α 만 분기. ϖ 분기는 효과 없음 |
| 이산화 (piecewise McCormick, NMDT: Castro 2016; Alpine) | 한쪽 변수를 이진 전개해 공간 분기를 MIP 분기로 | 아래 (4): 악화 |
| **정식화 선택** (pooling 의 P / Q / PQ: Tawarmalani–Sahinidis 2002) | 같은 문제도 곱을 어디에 두느냐로 완화가 크게 다르다 | **안 써 본 것 → 아래 (3)** |
| bilevel 전용: 상보성 분기·SOS1 (Bard–Moore), 강쌍대 부등식 (Kleinert–Labbé–Plein–Schmidt 2021), 교차 절단 (Fischetti–Ljubić–Monaci–Sinnl 2017/18) | 하위 문제 최적성을 분기·cut 으로 | WD 가 강쌍대 부등식과 같은 계열. KKT indicator 는 상한 0 (10.17). 교차 절단은 안 해 봄 |

**(2) 판단.** α·ϖ 는 "곱을 더 잘 완화하면 되는" 종류가 아니다. 리더 복사본의 recourse 최적성 cᵀŷ_s ≥ Q_s(α) 는 역볼록이고 (bilevel LP 의 하위 최적성), 최적 반응이 Q_s 의 꺾임 위에
있다. 꺾임을 품은 상자에서는 **가장 좋은 볼록 완화 (오목 포락) 도 오차가 상자 폭에 1 차** 다 (|x| 의 [−w/2, w/2] 위 오목 포락은 w/2). 따라서 BARON 의 더 강한 볼록화·범위 축소는
상수 배를 바꿀 뿐 "자유 좌표 20 개 × 폭에 1 차" 를 바꾸지 못한다. 전역 최적화 문헌이 이 구조에 주는 답은 완화가 아니라 (i) 꺾임에 맞춘 분기 (상보성·쌍대 조각), (ii) 정식화다.

**(3) 값함수 정식화 — 고정 x̄ 에서는 α 와의 곱이 필요 없다.** Ω 가 θ 벌점과 α·ϖ 를 쓰는 이유는 cut 이 x 에 affine 이고 Ω 가 x 와 무관해야 해서다. 상한 인증 (고정 x̄) 에는 그 제약이 없다.

    max  Σ_s r_s φ_s
    s.t. (a, r, d) ∈ 𝔅_δ,  α ∈ H,  y_s ∈ Y_s(x̄, α),  t_s = cᵀy_s,  φ_s = ℓᵀy_s
         c0ᵀα + Σ_s d_s t_s ≥ Σ_s b_sᵀπ̃_s + wᵀκ,   Aᵀπ̃_s ≥ d_s c,   Σ_s Hᵀπ̃_s + c0 ≤ Wᵀκ,   π̃, κ ≥ 0

- follower 의 2 단계 LP 는 실행가능 집합이 d 와 무관하고 d 는 목적에만 들어간다 → 쌍대 LP 가 (π̃, κ, d) 에 선형이고, 강쌍대 한 줄이 α ∈ Ψ(x̄, d) 와 같다.
- d_s > 0 이면 follower 최적인 (α, y) 의 y_s 는 recourse 최적이다 → **리더 복사본과 그 쌍대 ϖ 가 필요 없다** (y_s 가 recourse 최적해 집합을 움직이고 목적이 그 위에서 ℓᵀy 를 최대화).
- Ω 와의 차이는 "primal 을 belief 로 스케일하지 않는다" 는 것 하나다. Ω 는 ȳ = d·y, ŷ = r·y 로 스케일해 곱이 α×d, α×r (각 n_h·S 개) 과 α×ϖ 로 가고, 여기서는 곱이 스칼라 d_s × t_s, r_s × φ_s 의 **2S 개** 다.
  n_h = 50, S = 3 에서 Ω 는 곱 450 개 (Gurobi 프리솔브 뒤 198), 값함수 정식화는 6 개.
- RLT: 확률의 합 Σ_s d_s = 1, Σ_s r_s = 1 에 t_s', φ_s' 를 곱한 등식 (RLT1, pooling 의 pq 정식화와 같은 종류, 곱 2S²), 여기에 TV 볼·CVaR 행 × (t, φ 의 bound factor) 를 더한 것 (RLT2, 곱 5S²).
- 유효성 확인: SGB128 S = 3 x̄ = {1,2} 에서 −1470.5000 (KKT 값과 같음), 무작위 seed 1 은 [−1300.1667, −1299.03] (10.17 의 참값 [−1300.1667, −1300.1603] 을 품음), seed 2 x̄ = {2,3} 은 −2769.33 (10.17 의 −1269.33 + 출점비 1,500).

**(5) 한계 둘.**
- **d_s = 0.** q̂_s ≤ ε̃ 이면 (ε̃ = 0.3 에서 S ≥ 4) follower 가 확률 0 으로 믿는 시나리오가 생기고, 그 시나리오의 recourse 최적성은 follower 의 1 단계 최적성에서 나오지 않는다.
  값함수 정식화는 그때 유효한 상한일 뿐 정확하지 않다. 시도: recourse 쌍대의 **격자 이진화** — A 가 TU 이고 비용이 1/D 의 배수라 recourse 쌍대 꼭짓점의 예약 행 성분은
  {0, 1/D, …, p} 의 격자점이고, 이진 전개하면 α×σ 가 (이진 × 연속) 으로 정확히 선형화된다 (`VF_REC=lattice`). 정식화는 정확해지지만 Gurobi 의 상한이 0 에서 움직이지 않는다 (KKT indicator 와 같은 증상).
- **S 확장.** d_s ≥ 0.02 로 그 문제를 없애도 S = 5 는 600 s 에 53% 다. 분기 차원이 2(S − 1) 이고 동률면 둘레에서 완화 오차가 belief 상자 폭에 1 차라, 범용 솔버의 공간 분기로는 S = 3 까지다.
  즉 10.17 (3) 의 "유효 차원 min(n_h, S − 1)" 그대로이고, 달라진 것은 **S 가 작은 쪽을 기하 (셀 열거) 없이 정식화 + 범용 솔버로 풀 수 있다** 는 점이다.
