# 비제로섬 α-B&B 분석과 개선 방향 (2026-10-08 ~ 10-10)

zero-sum 에서 α-B&B (`true_dro/global_bilinear_solver.jl`) 는 Gurobi 전역보다 강했는데 (`docs/alpha_bnb_notes.md`: 루트 gap 3~6%,
S=50 에서 300 s 에 gap 0.07~0.26%), 비제로섬 (`nonzero_sum/nz_alpha_bnb.jl`, 기본 인스턴스 SGB128 + 예약 quota 150) 에서는
x = {1,2} 하나의 인증도 닫지 못했다. 원인 규명, 해결, 튜닝, 병목 측정, 다음 방향을 정리한다.
실험 표는 `experiments.md`, 원고 반영은 `paper/joc-non_zero_sum` (Lemma `lem:wd`, Remark `rem:theta-circuit`).

## 1. 원인: θ 벌점 항의 완화 오차

리더 블록은 F^L = ℓᵀŷ + θ(cᵀŷ − 쌍대목적) (pessimistic 평가의 정확 벌점). 정확한 점에서는 약쌍대성으로 θ 항 ≤ 0 (최적점에서 0).
완화에서는 primal 용량 (ζL = h^r·r) 과 쌍대목적 (ζW = h^r·ϖ) 이 따로 완화돼 **벌점이 보상으로 바뀐다**.
목적은 −158k (ŷ 항) 와 +190k (ϖ 항) 의 상쇄로 −1470 이 되는 구조라 오차가 θ × 비용 (마일) 으로 증폭된다.
zero-sum 은 θ = 0 (d_L = −d_F) 이라 이 항이 없고 곱의 상대가 확률이다.

증거 (`diag_box_width.jl`): 최적 α* 중심 폭 w 상자의 노드 상한 − V* 가 w 에 비례 (기울기 54.6/단위 폭) → 허용오차까지 활성 좌표마다 폭 ~0.003 필요.
분기 차원 (n_h = 15) 은 원인이 아님 (zero-sum 은 30~76).

## 2. 해결 (둘 다 증명 가능, 계산 비용 거의 없음)

| 해결 | 내용 | 효과 (x={1,2}, 600 s) |
|---|---|---|
| 정확한 circuit θᵁ | `nz_theta_circuit_exact`: Lemma phi (ii) 는 θᵁ ≥ max{ℓᵀg / (−cᵀg) : g circuit} 이면 충분. pair 수송 행렬의 circuit = 점포–고객 교대 경로 → 전수 열거. SGB128 θ̄ = 1 (기존 v / 해상도 = 5) | α-B&B gap 204% → 28%, Gurobi 95% → 0.22% |
| 약쌍대 부등식 (WD) | 시나리오마다 cᵀŷˢ ≤ (uˢ + gˢx̄)ᵀϖˢ + Σ hcoef ζWˢ. 최적점은 만족 → 값 불변, 줄인 집합의 점은 Ω 의 점 → cut 유효 | α-B&B 28% → 0.9%, Gurobi (60 s) 10% → 0.04%, 루트 상한 − V* 19,700 → 629 |

유효성: 16 개 x 에서 Ω (θᵁ=1 + WD) = KKT V* (위반 0). 원고: 본문 4.3 Lemma `lem:wd` + R(K) 의 (R3), 부록 증명 `app:proof-wd`, Remark `rem:theta-circuit`.

## 4. 튜닝 결과 (`tune_abb.jl`, 목표 gap 1e-3, 300 s)

- **분할점을 중점으로 (`branch_point=:mid`, 기본값으로 변경)**: S=20 gap ε=0.2 4.77% → 2.28%, ε=0.3 7.12% → 3.51%. α̂ 분할은 한쪽 자식이 얇아짐.
- diving 없음은 4 구성 모두 상한이 조금 나음 (차이 작음). 분리 라운드 수·가중 분기는 무관.
- 허용오차는 zero-sum 과 같은 0.5% 로 통일 (Benders tol 5e-3, α-B&B oracle gap 1e-3, Ipopt 120 s). 이전 비제로섬은 oracle 1e-5 / Benders 1e-4 로 500 배 엄격했음.

## 5. 남은 병목: 큰 S 에서 노드 LP 비용

S 스케일링 (θᵁ=1 + WD): S=3·20 은 Algorithm 2 가 최적 (S=20: ALGG Optimal 2,045 s, ALG gap 0.011%, SB 21~22%),
S=50·200 은 모든 방법이 x={1,2} 인증에서 막힘 (S=200: SB 271~351%, ALG 136%, ALGG 82%).

노드 LP 크기 (`diag_node_profile.jl`): 시나리오마다 리더 primal·쌍대, follower primal·쌍대 4 블록 + 곱 변수 → 변수 ~241·S, 제약 ~226·S
(S=200: 48k × 45k). 루트 LP: S=3 0.3 s, 20 0.4 s, 50 2.7 s, 200 57 s (분리 21 라운드).

시간 분해 (worker 합, `logs/tune_abb_timing*.log`):

| | 노드 | 완화 LP | α 고정 LP | 노드당 완화 LP | 한 경로 하강 시 |
|---|---|---|---|---|---|
| S=50, 300 s | 349~366 | 93% | 5% | ~9 s | 0.67 s |
| S=200, 300 s | 11~12 | 96% | 3% | ~96 s | 13.9 s |

- 시간의 93~96% 가 완화 LP. α 고정 LP 는 원인 아님.
- 실제 탐색이 한 경로 하강보다 7~13 배 느림 → **best-first 의 노드 전환으로 warm start 를 잃는 비용**.
- S=200 은 worker 의 72% 가 놂 (루트·초반 노드가 비싸 열린 노드가 부족).

## 6. 노드 완화 LP 의 구조 (OR 관점)

| 변수 묶음 | 크기 (S=200) | 등장 |
|---|---|---|
| 연결: h^r, belief (a,b,r,d,e,cpl), 곱 ζL·ζF·ζW, Z_a·Z_b·Z_e | ~80·S ≈ 16k | 시나리오 간 (Σ_s Z = h^r, TV 볼, CVaR, RLT) |
| 리더 블록 s: ŷ_s, ϖ_s, ρ̂_s | 65 / 시나리오 | 그 시나리오 행만 |
| follower 블록 s: ȳ_s, π̃_s, ρ̃_s | 65 / 시나리오 | 그 시나리오 행 + 집계 행 3 종 (follower 1 단계 KKT) |

- 연결 변수를 고정하면 리더 블록은 시나리오별 작은 LP 로 분리. 값은 (r_s, ζL_s, ζW_s) 에 대해 1 차 동차 → 절편 없는 선형 cut.
- follower 블록은 집계 행 (n_h + 1 + n_x 개) 으로만 묶임 → 집계량을 master 변수로 올리면 분리 가능.
- CVaR (β=0.4) 로 r 이 질량의 60% 이상에 퍼져 S=200 에서 활성 시나리오 120 개 이상 → 희소성 기법은 효과 작음 (실험과 일치).

## 7. 앞으로의 방향 (합의한 순서)

**C. 탐색 순서 (구현·측정 중)**: `node_select=:local` — 상한 상위 `local_k` 개 중 worker 가 직전에 푼 상자와 가장 가까운 노드.
연속 노드의 상자 변화를 줄여 warm start 유지. 변형 local8 / local32 / local8 + dive10 을 S=50·200 에서 base 와 비교 (`logs/tune_abb_local.log`).

**C 결과 (`logs/tune_abb_local.log`)**: S=50 처리량은 최대 +30% (350 → 456 노드, 노드당 완화 LP 9.2 → 7.1 s) 지만 상한 진행이
느려져 UB 는 오히려 나빠짐 (−791.1 → −782.1, local32 는 −574.5). S=200 은 11~12 노드로 차이 없음. → 탐색 순서는 해법이 아님.

**B. 빠른 실험 결과 (`logs/tune_abb_B.log`, 300 s)**

| | base | child3 | child1 | barrier |
|---|---|---|---|---|
| S=50 노드 / UB / gap | 374 / −797.7 / 25.3% | 537 / −829.7 / 22.0% | **814 / −852.9 / 19.6%** | 63 / −681.8 / 35.6% |
| S=200 노드 / UB | 11 / −471.9 | 15 / −471.3 | 20 / −463.3 | 3 / −428.1 |

- **자식 노드 분리 라운드 상한 (`child_rounds`) 이 지금까지 가장 효과적**: S=50 에서 child1 이 노드 2.2 배, UB −55. 부모 행이 유효해서
  자식 노드의 추가 라운드는 비싼 재풀이 대비 이득이 작음 → 노드에서 조이기보다 빨리 쪼개는 쪽이 유리.
- S=200 은 300 s 안에 루트 상한이 지배 (루트 LP 57 s, 21 라운드) → 자식 상한으로는 부족, A 로 루트 LP 자체를 줄여야 함.
- barrier 는 warm start 불가로 모든 S 에서 악화 → dual simplex 유지.
- 다음: S=20 에서 child1 vs child3 확인 후 기본값 결정 (`logs/tune_abb_child_S20.log`), 그다음 A.

**A. 노드 완화의 시나리오 분해 (L-shaped) + 전역 cut pool**
- master: 연결 변수 + 예약 행 인증서 ϖ_H (상자 의존 RLT 행이 들어가는 변수). 블록: ŷ_s, 나머지 ϖ_s, ρ̂_s (흐름·쌍대 실행가능성·Wcap·WD 행).
- 이렇게 나누면 블록 LP 가 상자 K 와 무관 → cut (블록 값 ≤ gᵀ연결변수) 이 트리 전체에서 유효 → **전역 cut pool 에 누적, 노드 간 재사용**.
  상자 의존 행 (ζW − l·ϖ ≥ 0 등) 을 블록에 두면 cut 은 그 노드의 subtree 에서만 유효하므로 그렇게 나누지 않는다.
- 노드마다: 누적 cut 으로 master 를 warm start → 연결 변수를 고정해 시나리오 블록 LP (65 변수, 병렬) → 위반 cut 만 추가 → 반복.
  초반엔 라운드가 많아도 cut 이 쌓이면 새 노드는 몇 라운드면 수렴할 것으로 예상.
- 관리: cut pool 크기 (오래 tight 하지 않은 cut 은 pool 로 빼고 위반 시 다시), follower 블록은 2 단계 (집계량을 master 로).
- master 에 남는 곱 변수 (~80·S) 축소는 별도 과제.

**제외**: α-B&B 와 Gurobi 병렬 실행 (리뷰어가 싫어할 수 있음, 2026-10-10 결정).

**A 결과: L-shaped 노드 완화 통합 (`node_lp=:lshaped`, `logs/tune_abb_lshaped.log`, 600 s, ε=0.3, δ=0.1, x={1,2})**

단일 노드 검증: full LP 와 값 일치 (≤ 1e-13). 노드당 시간 S=50 5.02 vs 4.84 s, S=200 89.9 vs 97.1 s, 루트 S=200 165 vs 52 s.
L-shaped 시간의 98% 가 master LP (연결 변수 ~80·S + cut 이 남아 master 가 작지 않음).

| 600 s | S=50 노드 / UB / gap | S=200 노드 / UB / gap |
|---|---|---|
| base (full 노드 LP, child_rounds=1) | **1418 / −907.2 / 14.6%** | **67 / −556.2 / 46.3%** |
| lsleader (리더 블록 분해, 공유 cut pool, in-out) | 824 / −861.2 / 18.3% (cut 3,106) | 38 / −527.4 / 48.9% (cut 5,536) |
| lsall (+ follower 분해 + MW) | 431 / −790.2 / 27.3% (cut 11,575) | 38 / −398.4 / 61.5% (cut 9,409) |

- 누적 시간 기준으로도 L-shaped 가 full 보다 나쁨. 분해를 더할수록 (follower, MW) 악화: cut 이 쌓이며 master 가 커지고, 새 상자에서 RLT 행과 cut loop 가 번갈아 여러 라운드 필요.
- S=200 은 L-shaped 루트가 느려 초반 열린 노드가 부족 → worker 합 노드 시간 3.3~3.8k s vs base 5.1k s (worker 유휴).
- 라운드 상한을 base 와 맞춘 `lsleader1` (루트 30 / 자식 1, `logs/tune_abb_lshaped1.log`): S=200 노드 44 / UB −492.9 / gap 52.2% → lsleader (50 / 3) 보다도 나쁨.
- **결론: 지금 형태의 L-shaped 는 채택하지 않음 (옵션으로 남김).**

**원인: 분해가 S 에 비례하는 층을 master 에 남김.** 블록 LP 를 상자와 무관하게 만들려고 상자 의존 RLT 행이 걸린 변수
(확률 a·b·r·d·e·cpl, 곱 ζL·ζF·ζW, ϖ_H, Z_a·Z_b·Z_e: ~80·S) 를 모두 master 에 두었다. 블록으로 빠진 것은 네트워크 흐름·쌍대 (65/시나리오) 뿐이라
LP 를 어렵게 만드는 확률·곱 층이 그대로 master 에 남았고, master LP 가 시간의 98%.
