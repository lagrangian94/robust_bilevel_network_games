# 비제로섬 α-B&B 분석과 개선 방향 (2026-10-08 ~ 10-10)

zero-sum 에서 α-B&B (`true_dro/global_bilinear_solver.jl`) 는 Gurobi 전역보다 강했는데 (`docs/alpha_bnb_notes.md`: 루트 gap 3~6%,
S=50 에서 300 s 에 gap 0.07~0.26%), 비제로섬 (`nonzero_sum/nz_alpha_bnb.jl`, 기본 인스턴스 SGB128 + 예약 quota 150) 에서는
x = {1,2} 하나의 인증도 닫지 못했다. 원인 규명, 해결, 튜닝, 병목 측정, 다음 방향을 정리한다.
실험 표는 `experiments.md`, 원고 반영은 `paper/joc-non_zero_sum` (Lemma `lem:wd`, Remark `rem:theta-circuit`).

## 1. 원인: θ 벌점 항의 완화 오차

리더 블록은 F^L = ℓᵀŷ + θ(cᵀŷ − 쌍대목적) (pessimistic 평가의 정확 벌점). 정확한 점에서는 약쌍대성으로 θ 항 ≤ 0 (최적점에서 0).
완화에서는 primal 용량 (ζL = h^r·r) 과 쌍대목적 (ζW = h^r·ϖ) 이 따로 완화돼 **벌점이 보상으로 바뀐다**.
목적은 −158k (ŷ 항) 와 +190k (ϖ 항) 의 상쇄로 −1470 이 되는 구조라 오차가 θ × 비용 (마일) 으로 증폭된다.
zero-sum 은 θ = 0 (d_L = −d_F) 이라 이 항이 없고 곱의 상대가 확률이다.

증거 (`diag_box_width.jl`): 최적 α* 중심 폭 w 상자의 노드 상한 − V* 가 w 에 비례 (기울기 54.6/단위 폭) → 허용오차까지 활성 좌표마다 폭 ~0.003 필요.
분기 차원 (n_h = 15) 은 원인이 아님 (zero-sum 은 30~76).

## 2. 해결 (둘 다 증명 가능, 계산 비용 거의 없음)

| 해결 | 내용 | 효과 (x={1,2}, 600 s) |
|---|---|---|
| 정확한 circuit θᵁ | `nz_theta_circuit_exact`: Lemma phi (ii) 는 θᵁ ≥ max{ℓᵀg / (−cᵀg) : g circuit} 이면 충분. pair 수송 행렬의 circuit = 점포–고객 교대 경로 → 전수 열거. SGB128 θ̄ = 1 (기존 v / 해상도 = 5) | α-B&B gap 204% → 28%, Gurobi 95% → 0.22% |
| 약쌍대 부등식 (WD) | 시나리오마다 cᵀŷˢ ≤ (uˢ + gˢx̄)ᵀϖˢ + Σ hcoef ζWˢ. 최적점은 만족 → 값 불변, 줄인 집합의 점은 Ω 의 점 → cut 유효 | α-B&B 28% → 0.9%, Gurobi (60 s) 10% → 0.04%, 루트 상한 − V* 19,700 → 629 |

유효성: 16 개 x 에서 Ω (θᵁ=1 + WD) = KKT V* (위반 0). 원고: 본문 4.3 Lemma `lem:wd` + R(K) 의 (R3), 부록 증명 `app:proof-wd`, Remark `rem:theta-circuit`.

## 6. 노드 완화 LP 의 구조 (OR 관점)

| 변수 묶음 | 크기 (S=200) | 등장 |
|---|---|---|
| 연결: h^r, belief (a,b,r,d,e,cpl), 곱 ζL·ζF·ζW, Z_a·Z_b·Z_e | ~80·S ≈ 16k | 시나리오 간 (Σ_s Z = h^r, TV 볼, CVaR, RLT) |
| 리더 블록 s: ŷ_s, ϖ_s, ρ̂_s | 65 / 시나리오 | 그 시나리오 행만 |
| follower 블록 s: ȳ_s, π̃_s, ρ̃_s | 65 / 시나리오 | 그 시나리오 행 + 집계 행 3 종 (follower 1 단계 KKT) |

- 연결 변수를 고정하면 리더 블록은 시나리오별 작은 LP 로 분리. 값은 (r_s, ζL_s, ζW_s) 에 대해 1 차 동차 → 절편 없는 선형 cut.
- follower 블록은 집계 행 (n_h + 1 + n_x 개) 으로만 묶임 → 집계량을 master 변수로 올리면 분리 가능.
- CVaR (β=0.4) 로 r 이 질량의 60% 이상에 퍼져 S=200 에서 활성 시나리오 120 개 이상 → 희소성 기법은 효과 작음 (실험과 일치).

**A. 노드 완화의 시나리오 분해 (L-shaped) + 전역 cut pool**
- master: 연결 변수 + 예약 행 인증서 ϖ_H (상자 의존 RLT 행이 들어가는 변수). 블록: ŷ_s, 나머지 ϖ_s, ρ̂_s (흐름·쌍대 실행가능성·Wcap·WD 행).
- 이렇게 나누면 블록 LP 가 상자 K 와 무관 → cut (블록 값 ≤ gᵀ연결변수) 이 트리 전체에서 유효 → **전역 cut pool 에 누적, 노드 간 재사용**.
  상자 의존 행 (ζW − l·ϖ ≥ 0 등) 을 블록에 두면 cut 은 그 노드의 subtree 에서만 유효하므로 그렇게 나누지 않는다.
- 노드마다: 누적 cut 으로 master 를 warm start → 연결 변수를 고정해 시나리오 블록 LP (65 변수, 병렬) → 위반 cut 만 추가 → 반복.
  초반엔 라운드가 많아도 cut 이 쌓이면 새 노드는 몇 라운드면 수렴할 것으로 예상.
- 관리: cut pool 크기 (오래 tight 하지 않은 cut 은 pool 로 빼고 위반 시 다시), follower 블록은 2 단계 (집계량을 master 로).
- master 에 남는 곱 변수 (~80·S) 축소는 별도 과제.

**제외**: α-B&B 와 Gurobi 병렬 실행 (리뷰어가 싫어할 수 있음, 2026-10-10 결정).

**A 결과: L-shaped 노드 완화 통합 (`node_lp=:lshaped`, `logs/tune_abb_lshaped.log`, 600 s, ε=0.3, δ=0.1, x={1,2})**

단일 노드 검증: full LP 와 값 일치 (≤ 1e-13). 노드당 시간 S=50 5.02 vs 4.84 s, S=200 89.9 vs 97.1 s, 루트 S=200 165 vs 52 s.
L-shaped 시간의 98% 가 master LP (연결 변수 ~80·S + cut 이 남아 master 가 작지 않음).

|---|---|---|

- S=200 은 L-shaped 루트가 느려 초반 열린 노드가 부족 → worker 합 노드 시간 3.3~3.8k s vs base 5.1k s (worker 유휴).

- **결론: 지금 형태의 L-shaped 는 채택하지 않음 (옵션으로 남김).**

**원인: 분해가 S 에 비례하는 층을 master 에 남김.** 블록 LP 를 상자와 무관하게 만들려고 상자 의존 RLT 행이 걸린 변수
(확률 a·b·r·d·e·cpl, 곱 ζL·ζF·ζW, ϖ_H, Z_a·Z_b·Z_e: ~80·S) 를 모두 master 에 두었다. 블록으로 빠진 것은 네트워크 흐름·쌍대 (65/시나리오) 뿐이라
LP 를 어렵게 만드는 확률·곱 층이 그대로 master 에 남았고, master LP 가 시간의 98%.

### 10.3 새 강화 (모두 유효 부등식, `nz_alpha_bnb_dr.jl`)

정확한 해에서 인증서 ϖˢ/r_s (리더 블록), π̃ˢ/d_s (follower 블록) 는 시나리오 s recourse LP 의 **α 에서의 최적 쌍대** 이고 α 는 노드 상자 B 안에 있다.

| 이름 | 내용 | 계산 |
|---|---|---|
| 쌍대 범위 (W, F) | H 행 성분 σ_ks ∈ [σlo(B), σhi(B)] = 상자 안 어떤 α' 에서 최적인 쌍대의 범위 (전역 [0, p] 대신). σlo r ≤ ϖ ≤ σhi r, σlo d ≤ π̃ ≤ σhi d + 이 행 × α 상자 인수의 RLT | 시나리오·행마다 작은 KKT-MIP 2 개 |
| C | 상자가 함의하는 상보성: l_i > 0 이면 follower 1단계 정상성이 등식, Σ W_li u_i < w_l 이면 κ_l = 0 | 없음 |
| V | 시나리오별 값 상한 ℓᵀŷˢ ≤ φ̄_s(B) r_s, φ̄_s(B) = max_{α∈B} φ_s(α) | 시나리오마다 MIP 1 개 |
| X | follower 1단계 상보성 α_i·slack_i = 0, κ_l·slack_l = 0 의 RLT (곱 변수 Zκ = α κ, ζΠ = α π̃) | 없음 (범위 사용) |

  (S = 3, w = 1 에서 고정된 성분 9/27 → 21/27). 우변이 양수인 행은 자동으로 성립하고 α_i = 0 인 행은 낮춰도 최적이 유지되므로 일반성을 잃지 않는다.
- witness 캐시: 부모 MIP 의 해 α 가 자식 상자 안에 있으면 그 값은 자식에서도 그대로 → 재풀이 생략 (노드당 MIP 18 → 8 개).

### 10.3.1 "실제로 최적이 될 수 있는 쌍대값 범위로 조인다" 를 풀어 쓰면

**쌍대값이 무엇인가.** 시나리오 s 의 recourse (follower 의 2 단계) 는 Q_s(α) = max{cᵀy : Ay ≤ ρ_s(α)} 이고 그 쌍대는
min{ρ_s(α)ᵀσ : Aᵀσ ≥ c, σ ≥ 0} 이다. 예약 행 k = (점포 i, 고객 j) 는 y^R_ij ≤ α_ij 이고, 그 쌍대값 σ_ks 는
"시나리오 s 에서 예약을 한 단위 더 해 두었다면 follower 비용이 얼마나 줄었는가" (예약의 한계가치) 다.
location 인스턴스에서는 예약분은 c_ij, 현장구매는 c_ij + p (p = 200) 이므로

| 시나리오 s 의 상황 | σ_ks |
|---|---|
| 수요가 예약보다 많다 (ξ_js > α_ij: 예약을 다 쓰고 현장구매까지 함) | p = 200 (한 단위 더 예약했으면 프리미엄을 아낌) |
| 수요가 예약보다 적다 (ξ_js < α_ij: 예약이 남음) | 0 |
| 딱 같다 (ξ_js = α_ij) | 0 ~ 200 사이 아무 값 (**꺾임점**) |

(용량이 묶이거나 더 싼 점포의 예약이 있으면 중간값도 나온다. 위 표는 가장 단순한 경우.)

**Ω 에서 이 값이 어디에 쓰이나.** Ω 의 인증서 변수가 바로 이 쌍대다: 리더 블록의 ϖ_ks = r_s σ_ks, follower 블록의 π̃_ks = d_s σ_ks.
비볼록 항 ζW = α_ij · ϖ_ks 가 여기서 나온다. 기존 완화는 σ 에 대해 **전역 범위 0 ≤ σ ≤ 200** (Wcap: ϖ ≤ p r) 만 알고 있어서,
α 와 ϖ 의 곱을 [0, 150] × [0, 200 r] 상자 위의 McCormick 으로 푼다 — 완화 오차의 대부분이 여기서 나온다.

**조인다는 것.** B&B 노드는 α 의 상자 B = [l, u] 다. 예를 들어 α_ij ∈ [100, 120] 인 노드를 보자.

| 시나리오의 수요 ξ_js | 상자 안 모든 α 에서 | 쓸 수 있는 범위 | 곱 ζW = α ϖ |
|---|---|---|---|
| 150 | 항상 예약을 다 씀 | σ = 200 으로 **고정** | ϖ = 200 r → ζW = 200·(α r) = 200 ζL: **선형, 정확** |
| 60 | 항상 예약이 남음 | σ = 0 으로 **고정** | ϖ = 0 → ζW = 0: **정확** |
| 110 (상자 안에 꺾임) | α 에 따라 다름 | [0, 200] 그대로 | 여전히 느슨 |

즉 "이 상자 안의 어떤 α 에서든 최적 쌍대가 될 수 있는 값" 만 남긴다. 꺾임점이 상자 밖에 있는 시나리오는 쌍대가 한 점으로 고정되고,
그 순간 그 시나리오의 인증서 곱은 완화가 아니라 정확한 식이 된다. 상자가 작아질수록 꺾임을 품는 시나리오는 줄어든다
(S = 10, 폭 3 인 상자: 90 개 성분 중 83 개 고정). 느슨함이 "모든 시나리오" 에서 "꺾임이 상자 안에 있는 몇 개" 로 줄어드는 것이 효과의 전부다.

**범위는 어떻게 구하나.** 위 표처럼 수요와 상자를 비교하는 규칙은 쓰지 않는다 (용량·다른 점포 예약과 얽히면 틀림). 대신 시나리오 s 마다
작은 MIP 를 푼다: "α ∈ B 이고 (y, σ) 가 α 에서 시나리오 s recourse LP 의 최적 primal–dual 쌍 (상보성 조건을 이진변수로)" 을 만족하는 점 중
σ_k 의 최솟값과 최댓값. 변수 수십 개짜리라 한 개에 1~4 ms 이고, 부모 노드에서 이미 고정된 성분은 다시 풀지 않는다.
이 방식은 newsvendor 구조를 가정하지 않으므로 일반 LP recourse (`NZData`) 에 그대로 적용된다.

**노드 LP 에 들어가는 것.**
- 범위 행: σlo·r_s ≤ ϖ_ks ≤ σhi·r_s (리더 인증서), σlo·d_s ≤ π̃_ks ≤ σhi·d_s (follower 인증서).
- 이 행과 상자 인수의 곱 (RLT): (ϖ − σlo r)(α − l) ≥ 0 등 4 개. σlo = σhi 이면 ζW = σ ζL 로 떨어진다.

**왜 유효한가 (최적해를 잘라내지 않는가).** Ω 의 최적해에서 인증서는 **참 α 에서의** 최적 쌍대이고, 그 α 는 이 노드의 상자 안에 있다
(상자 밖이면 다른 노드가 담당). 따라서 "상자 안 어딘가에서 최적인 쌍대" 의 범위는 그 인증서를 반드시 포함한다. 줄어든 집합의 점은
여전히 Ω 의 점이므로 거기서 만든 Benders cut 도 유효하다. Wcap (ϖ ≤ p r) 이나 약쌍대 부등식 (WD) 과 같은 종류의 논증이다.
주의할 점 하나: α_ij = 0 (예약 안 함) 에서는 "한 단위 더" 의 가치가 [실제 한계가치, 200] 전체가 쌍대로 허용돼 범위가 부풀어 버린다.
이때는 더 낮출 수 없는 가장 작은 쌍대만 써도 최적성이 유지되므로 그렇게 제한한다 (이 제한이 없으면 효과가 거의 사라짐).

**나머지 세 강화는 같은 생각의 연장이다.**
- C (상자가 함의하는 상보성): 상자에서 α_i > 0 이 확실하면 follower 의 1 단계 최적성 조건 (newsvendor 식의 "한계가치의 기댓값 = 예약비")
  이 부등식이 아니라 **등식** 이다. 이 등식이 belief d 를 직접 묶는다.
- V (시나리오별 값 상한): 시나리오 s 의 리더 손실 φ_s(α) 가 상자 위에서 가질 수 있는 최댓값을 같은 MIP 로 구해 ℓᵀŷˢ ≤ φ̄_s r_s 로 막는다.
  쌍대가 고정되지 않은 (꺾임을 품은) 시나리오와 루트처럼 큰 상자에서 효과가 크다 (루트 상한 − V* : 730 → 329).
- X (상보성의 RLT): follower 의 상보성 조건 α_i × (1 단계 쌍대 여유) = 0 은 곱이라 그대로는 못 쓰지만, 곱 변수 (α κ, α π̃) 로 쓰면 선형 등식이 된다.
  10.2 에서 본 "F (α·d) 도 같이 조여야 한다" 에 해당하는 부분이다.

### 10.6 유효성과 수치 문제

**직접 검사** (`test_dr_validity_boxes.jl`): B&B 의 [LB, UB] ∋ V* 만으로는 약하다 (휴리스틱이 LB 를 V* 근처로 올리면, α* 를 품은 상자가
잘못 잘려도 UB ≥ LB 라 안 드러남). 그래서 독립 KKT 평가기의 최적 반응 α* 를 **품는 무작위 상자** 에서 노드 완화가 실행 가능하고 상한 ≥ V* 인지 본다.

| | 상자 | 상한 < V* | 재확인에서도 실행 불가능 |
|---|---|---|---|
| S = 3, x̄ ∈ {{1,2}, {1}, {2}, {1,2,3}}, 폭 ≥ 0.01, 변형 4 종 (W+F+C / +V / +X / 전부) | 1,600 | 0 | 0 |
| S = 5, x̄ = {2} (KKT 가 600 s 에 끝난 것만), 변형 2 종 | 120 | 0 | 0 |

**거짓 실행 불가능 판정.** 범위 행을 넣은 노드 LP 는 실행 가능한데도 INFEASIBLE 로 나오는 일이 있다 (위 검사에서 첫 판정 기준 0.5~1%,
범위 행이 없는 기존 완화는 400 개 중 0). 수학적 무효가 아니라 수치 문제라는 근거:
- 같은 상자를 새 모델에서 풀면 OPTIMAL.
- 제약이 더 많은 변형 (전부) 은 실행 가능한데 더 적은 변형 (X 만) 이 실행 불가능으로 나오는 경우가 있다 (제약을 빼서 실행 불가능해질 수는 없음).
- 점 상자 [α*, α*] 에서는 상한 = V*.

원인은 노드마다 행렬 계수를 바꾼 뒤 이어 푸는 dual simplex + `FeasibilityTol = 1e-9` (build_nz_omega 의 설정). FeasibilityTol 만 1e-6 으로
풀고 이어 풀면 그대로 실행 불가능이고, **기저를 버리고 (GRBreset) primal simplex 로 1e-6 에서 처음부터** 풀면 풀린다
(`_nz_dr_recheck_infeasible!`). 지금은 INFEASIBLE 판정마다 이 재확인을 거친 뒤에만 가지치기한다. 최종 측정에서 재확인으로 되살아난 노드:
S = 3 에서 463 개 중 89, S = 20 에서 43 개 중 8.

**남은 것**
- 재확인을 통과한 "실행 불가능" 이 전부 진짜인지는 증명하지 못했다 (검사에서는 α* 를 품은 상자 1,720 개 중 0). 근본 대책은 계수를 바꾸지 않는
  정식화이거나 실행 불가능 판정을 Farkas 인증서로 검증하는 것.
- 범위 MIP 의 `Gurobi Error 10005` (worker 12 개 첫 실행에서 worker 전멸, `logs/scale_oracle_dr2_failed_S3.log`): 이후 실행에서는 0 회, 원인 미확인.
  한 번 재시도 후 실패하면 그 성분을 부모 범위로 두고 (유효) 횟수를 `:range_fail` 로 보고한다.
- `F` (π̃ 범위) 는 "H 행 성분이 ϖᵁ 이하이고 더 낮출 수 없는" 2 단계 LP 최적 쌍대의 존재를 쓴다. location 에서는 성립하지만
  (τ = (μ − κ − c d)⁺ ≤ p d) 일반 `NZData` 에서는 가정이다.
- Benders 와는 10.7 에서 연결했다. 탐색 루프는 여전히 새 파일에 복사한 상태 (`nz_alpha_bnb.jl` 과 합치지 않음).

배제해서 oracle 이 인증해야 하는 것은 쉬운 x = {1} 뿐이기 때문이다 (기존 111 s, 새 54 s). 새 α-B&B 가 결정적인 곳은 어려운 x̄ 를 인증해야 하는
SB-A (TimeLimit → 479 s) 다. Algorithm 2 도 최적 x̄ 자체의 인증이 어려우면 같은 차이가 날 것이다 (x = {1,2} 의 oracle 만 보면 S = 30 에서
600 s 에 9.3% vs 1.1%). 다만 S = 30 에서 어느 x̄ 가 최적인지, Algorithm 2 가 그 인증을 요구하는지는 아직 재지 않았다.

없앴다. Ω(x̄) 는 x̄ 만으로 정해지므로 이전 호출이 남긴 B&B 전선 (열린 노드와 상한, 가지친 노드의 상한, incumbent) 은 같은 x̄ 에서 그대로 유효하다.
`nz_alpha_bnb_dr` 가 끝날 때 상태 (`r[:state]`) 를 돌려주고 `resume` 로 받으면 거기서 이어 푼다. Benders 는 최근 6 개 x̄ 의 상태를 보관 (기본 켬).
대안이던 "최적 후보 x̄ 에서는 조기 종료를 끄기" 는 어느 x̄ 가 최적 후보인지 추측해야 하고, 틀리면 SB-A 처럼 비최적 x̄ 의 인증에 묶이므로 넣지 않았다.

- Gurobi 를 전역 솔버로 쓰는 방법 (SB-G, ALGG) 은 S = 30 에서 둘 다 1 시간 안에 못 푼다. α-B&B 를 쓰는 방법은 모두 풀고, 기본 구현이 기존보다 2.4~6 배 빠르다.

### 10.11 꺾임 정보를 쓰는 두 시험: 분할 위치, 계단 cut (2026-10-12, 둘 다 채택 안 함)

10.10 의 후보 1 을 시험했다. oracle 단독, S = 20, x̄ = {1,2}, worker 12, 목표 gap 1e-3, 600 s. 기준은 기본 구성 (중점 분할) 의 10.10 실행.

**(a) 꺾임 사이 분할** (`branch_point=:kinkmid`, 커밋 b3775b2 의 `_nz_dr_kinkpts`·`_nz_kink_split`).
분기 좌표 i 가 정해지면, 그 좌표의 고정 안 된 성분 (k, s) 마다 범위 MIP 두 개로
p⁺ = max{α_i : σ_k 가 아직 hi 일 수 있음}, p⁻ = min{α_i : σ_k 가 이미 lo 일 수 있음} 을 구해 상자 안 꺾임 위치로 삼고,
꺾임 수가 절반씩 되도록 가운데 두 꺾임의 중간에서 나눈다 (1 개면 넓은 쪽 틈의 가운데, 0 개면 중점. 경계 5% 안쪽으로 자름).

**(b) 계단 cut** (`stepcut`, 커밋 a686019 의 `_nz_dr_steps`). 꺾임 위치를 분할이 아니라 완화에 넣는다.
P = p⁺ + η 에서 좌표 i 를 나눈 오른쪽 자식의 범위 hiR = max{σ_k : α ∈ B, α_i ≥ P} 를 미리 구하면 B 에서
σ_k ≤ hi (α_i < P), σ_k ≤ hiR (α_i ≥ P) 이고, 이 계단의 오목 포락선 σ_k ≤ hi − (hi − hiR)(α_i − P)/(u_i − P) 가 유효하다
(아래쪽도 대칭). r_s 를 곱하면 ϖ, r, ζL 의 선형 행 (follower 쪽은 π̃, d, ζF). 유효성은 자식 상자 범위의 정의에서만 나온다.
S = 3 의 α* 를 품은 무작위 상자 300 개 (cut 1,293 개) 에서 상한 < V* 0 건 (`logs/test_dr_validity_boxes_step_S3.log`).

| (a) 꺾임 사이 분할 | 602 s, 1,362 노드 | 606 s 에 2.02%, 1,318 노드 |

### 10.13 정체의 원인과 해결 (2026-10-13) — seed 3 의 oracle 이 1 시간 0.64% → 94 초에 0.1%

정체한 전선을 저장해 놓고 **같은 상자 묶음에서 완화와 LP 설정을 바꿔 가며** 본 결과 (아래 진단 스크립트), 원인은 탐색이 아니라

#### (1) worker 병렬의 GC 대기 (`gurobi_gcsafe.jl`)

Julia 의 GC 는 stop-the-world 라 한 스레드가 GC 를 시작하면 모든 스레드가 safepoint 에 닿을 때까지 기다리는데, **ccall 안의 스레드는
safepoint 가 아니다.** worker 하나가 Gurobi LP 를 푸는 동안에는 GC 가 시작되지 못하고, 그 사이 LP 를 끝낸 다른 worker 는 메모리 할당
지점에서 멈춘다. worker 12 개가 번갈아 LP 를 풀면 이 대기가 겹친다.

| 120 s 실행 (tol 1e-7 + FWD) | 노드 | safepoint 대기 (`Base.gc_num().total_time_to_safepoint`) | GC 자체 |
|---|---|---|---|
| 그대로 | 373 | 82.0 s | 1.1 s |
| Ipopt 휴리스틱 끔 | 479 | 80.0 s | 1.0 s |
| GRBoptimize 를 GC-safe 구간에서 | 860 | 0.3 s | 2.6 s |

wall 120 s 중 82 s 동안 전체가 멈춰 있었다 — worker 12 개가 4 개 남짓으로 돈 셈이다. 10.10 의 "worker 유휴 20~28%",
8 절의 "worker 12 개 동시 barrier 는 경쟁으로 LP 1 회 3.4 → 13.8 s", "worker 6 이 처리량 거의 같음" 은 이것으로 설명된다 (그때는 메모리 경쟁으로 봤다).
`gurobi_gcsafe.jl` 은 Gurobi 모듈의 `GRBoptimize` 를 `jl_gc_safe_enter` / `jl_gc_safe_leave` 사이에서 부르도록 덮어쓴다
(Julia 1.12 의 `@ccall gc_safe=true` 와 같은 일). `nz_alpha_bnb_dr.jl` 이 include 하고 `NZ_GCSAFE=0` 으로 끈다. 결과 Dict 의 `:gc_wait`.
**이 패치 전의 α-B&B 시간·노드 수 (10.12 까지 전부) 는 패치 후와 직접 비교할 수 없다.** 기존 구현 `nz_alpha_bnb` 도 같은 프로세스에서는 혜택을 받는다.

#### (2) 노드 LP: 허용오차와 행 관리

- **허용오차** (`lp_tol = 1e-7`). `build_nz_omega` 는 θ 항의 상쇄 때문에 FeasibilityTol = OptimalityTol = 1e-9, NumericFocus 2 로 둔다
  (θᵁ = 1200 이던 때의 설정). 같은 상자 66 개에서 1e-7 + NumericFocus 0 은 상자당 LP 5.14 s → 0.69 s 이고 가지치기되는 상자 수는 같다 (20 → 21).
  NumericFocus 만 0 으로 하면 3.99 s 라 원인은 허용오차다. 덜 수렴한 목적값을 상한으로 쓰는 것에 대비해 노드 상한에 상대 1e-6 을 더한다.
- **분리 행 제자리 갱신** (`sticky`). 기존 방식은 상자 경계가 다른 RLT 행을 새로 쌓고 안 맞는 행은 rhs = −∞ 로 꺼 둔다. worker 의 LP 가
  계속 커지고 (10.12: 30 분에 분리 행 2 만 개, 처리량 1/3), 자식 노드에는 부모 경계의 느슨한 행만 남아 분리 라운드를 더 돌아야 조여진다
  (같은 상자에서 라운드 1 → 30 이면 가지치기 21 → 31 개, 그러나 `child_rounds = 4` 는 LP 횟수 때문에 시간으로는 손해: 0.39% → 0.59%).
  제자리 갱신은 (좌표 i, 후보 행 j, 쪽) 마다 LP 행을 하나만 두고 상자가 바뀌면 경계 b 를 지금 상자의 l_i (u_i) 로 바꾼다.
  LP 크기가 묶이고 노드에 들어설 때 모든 행이 이미 지금 상자 기준이다. 10 분 처리 노드 2,884 → 7,895, gap 0.27% → 0.11%.
  10.12 의 "처리량이 시간에 따라 1/3 로 준다" 의 원인은 쌓인 행이었다.

#### (3) follower 블록 완화에 빠져 있던 것

`lab_blame.jl`·`lab_inspect.jl` 로 정체한 상자의 노드 LP 해를 뜯어 보면, **리더 블록은 정확하다** (Σ_s r̂_s φ_s(α̂) = 노드 상한, 시나리오별 α 도 α̂ 와 같음).
상한이 LB 보다 높은 것은 α̂ 가 리더에게 유리한 점인데 **어떤 belief 로도 follower 최적이 아니어서** 다 (α̂ 고정 정확 LP 는 벌점 수천).
즉 남은 오차는 전부 follower 최적성 (F) 쪽이고, 다음 셋이 그것을 막는다.

| 이름 | 내용 | 왜 빠져 있었나 |
|---|---|---|
| FWD | 시나리오별 약쌍대 cᵀȳˢ ≤ (uˢ + gˢx̄)ᵀπ̃ˢ + Σ_{k∈H} hcoef_k ζΠ_ks | Flam (합친 강쌍대) + X 의 항등식은 Σ_s [쌍대목적_s − primal_s] ≤ 0 만 준다. 꺾임을 품은 상자에서는 시나리오끼리 부호가 다른 gap 을 상쇄한다. 리더 블록에는 같은 행 (WD) 이 있었고 follower 블록에는 곱 변수 ζΠ 가 X 와 함께 뒤늦게 생겨서 없었다 |
| 상보성 분기 | l_i = 0 인 좌표에서 α̂_i > 0 이고 정상성 여유 ĝ_i > 0 이면 {α_i = 0} \| {g_i = 0, 상자 그대로} 로 분기 | C 는 l_i > 0 일 때만 정상성을 등식으로 둔다. 중점 분할의 왼쪽 자식 [0, u/2] 에는 완화된 상보성 (α_i ≤ u_i (1 − g_i / gmax)) 이 그대로 남아 오차가 폭에 비례해 반씩만 준다 — 10.2 의 "기울기 ~5 / 단위 폭" 의 한 출처 |
| DD | 쌍대 **차이** 의 범위 dlo ≤ σ_k − σ_k′ ≤ dhi (같은 KKT-MIP, 목적만 σ_k − σ_k′). dlo d_s ≤ π̃_ks − π̃_k′s ≤ dhi d_s, 리더는 ϖ 와 r_s | 성분별 범위 [lo, hi] 는 곱집합이라 두 쌍대가 함께 움직이는 것을 놓친다 |

DD 가 잡는 것의 예 (정체한 상자 하나, `lab_inspect.jl`): 고객 3 은 B1 (수송비 217) 과 A (258) 에 예약할 수 있다. 수요가 두 예약의 합을 넘는 시나리오에서
두 예약의 한계가치는 (200, 159), 그 아래에서는 (41, 0) 이라 **차이는 늘 41** 이다. 성분별 범위는 [41, 200] × [0, 159] 라 LP 는 (41, 62) 를 고른다.
차이가 41 로 묶이면 두 좌표의 정상성 Σ_s π̃ = f + κ 가 동시에 등식일 수 없고 (B1 한도가 남는 한), 따라서 A 예약 α_3 > 0 인 자식은 바로 실행 불가능이 된다.
이것은 "더 싼 점포의 한도가 남아 있으면 비싼 점포에 예약하지 않는다" 는 지배 관계인데, 인스턴스 구조를 쓰지 않고 범위 MIP 가 찾아낸다.
노드당 범위 MIP 는 37 → 69 개 (노드당 0.17 s) 로 늘고 노드 수는 6,012 → 588 로 준다.

KMC (κ_l ≤ κmax_l = max_i (Σ_k hcoef_k ϖᵁ_k + c0_i) / W_li 와 Zκ = α κ 의 위쪽 McCormick) 는 상자가 넓고 α̂_i = 0 인 좌표에서
Zκ_il 이 u_i κ_l 까지 자유로워 한도 상보성 κ_l (w_l − W_l α) = 0 의 선형화가 비는 것을 막는다. 같은 상자 묶음에서는 효과가 작았고 (가지치기 40 → 41) 상보성 분기와 함께 넣었다.

#### (4) 실행 불가능 재확인의 비용 (`lab_recheck.jl`)
