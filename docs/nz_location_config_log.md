## 4. 변경 경위 (시간순)

### 4.1 이전 기준: `toptier`, `dwtier` (2026-11-14)

- **설정.** 예약료 0.25, 메뉴 200·250·300, 예약 상한 300. 지리 15 × 시드 5 = 75 건씩.
- **결과.** 리더가 진짜를 아는 세계에서 Belief-only ($\delta = 0.1$) 꼬리 우위 −3.0 ± 0.6 ($N_F = 5$), −3.2 ± 0.5 ($N_F = 20$). 자료 세계에서 Data-DR 은 96~99% 에서 Nominal 과 같은 결정.
- **드러난 문제.** 추가 주문 비중 0.1%. 리더 판매가 모든 시나리오에서 $h$ 로 같아서 Data-DR 이 헤징할 것이 없다. 사용자 지적: 소매상의 수송 문제 중요성을 없애 버린 구성이다.

### 4.2 노출 선별 1 차: `expo0`~`expo7` (2026-11-15 새벽)

- **왜.** 사용자 요구 두 가지를 같이 만족하는 구성을 찾기 위해서다. (1) 추가 주문이 리더 수입에 영향을 줄 만큼 있을 것, (2) 예약의 중요성이 남아 belief 헤징이 사라지지 않을 것.
- **무엇을 바꿨나.** 용량 메뉴 상한 (300 → 400), 예약 상한 (300 → 200), 예약료 비율 (0.25 → 0.33·0.4·0.5).
- **어떻게.** 지리 g1~4 × 시드 1, 결정 전수 열거 후 Nominal 결정의 추가 주문 비중, 자료 노출, belief 노출을 잰다 (`expo.jl`). 본 평가가 아니라 선별이다.
- **결과.** 메뉴 상한만 올려서는 추가 주문이 안 생긴다. 예약 상한을 200 으로 내리면 추가 주문은 9~11% 생기지만 belief 노출이 8.6 → 1 로 죽는다. 예약료 0.5 까지는 추가 주문 1% 안팎.
- **결론.** 예약 상한은 손잡이가 아니다 (300 유지). 예약료를 더 올려 봐야 한다.

### 4.3 노출 선별 2 차: `expo8`~`expo11` (2026-11-15 오전)

- **왜.** 한 거점 논리로는 추가 주문의 몫이 $1 - (1 - f/p)/(1 - \beta)$ 라서 예약료 0.4 를 넘어야 생기고, 그 몫이 용량비보다 커야 리더가 여유 용량을 짓는다.
- **무엇을 바꿨나.** 예약료 비율 0.5·0.6·0.67·0.75, 용량비 0.2 추가. 메뉴 200·300·400, 예약 상한 300.
- **결과.** 예약료 0.67~0.75 에서 추가 주문 4~6% (용량비 0.5·0.4), belief 노출 7~11 로 둘 다 산다.
- **결론.** 손잡이는 예약료 비율이다. 본 평가를 0.75 와 0.67 에서 돌린다.

### 4.4 새 구성 본 평가: `tkv75`·`tkv67`, `dw75`·`dw67` (2026-11-15 오전)

- **이전 기준과 다른 점.** 예약료 비율 (0.25 → 0.75, 0.67) 과 용량 메뉴 (200·250·300 → 200·300·400) 둘이다. 나머지는 같다.
- **스크립트.** 리더가 진짜를 아는 세계는 `tkV.jl` (이전의 `tkT.jl` + 층화 후보를 한 번에 평가). 자료 세계는 `dwTier.jl` 그대로.
- **건수.** 처음에 지리 15 × 시드 1. 이후 시드 2·3 을 걸었다가 4.6 에서 멈췄고, 4.7 에서 0.75 만 다시 걸었다.
- **결과 (중간).** `tkv75` 30 건: 꼬리 우위 −2.0 ± 0.6 ($N_F = 5$), −1.6 ± 0.5 ($N_F = 20$), 용량비 0.5. `dw75` 15 건은 가설 문서 8.8.

### 4.5 메뉴 진단: `expo12` (2026-11-15 오전)

- **왜.** 사용자 질문 "용량 후보를 잘 준비했는가". 메뉴 200·300·400 에서 Nominal 이 최저 단계를 60~64% 골랐고 한 단계 차이가 5% 였다.
- **무엇을 바꿨나.** 메뉴만 100·150·200·250·300 으로 (예약료 0.75, 지리 g1~4).
- **결과.** 추가 주문·자료 노출·belief 노출이 메뉴 200·300·400 과 거의 같다. 추가 주문은 메뉴 탓이 아니다. 100 은 안 쓰이고 300 상한은 묶인다.

### 4.6 여섯 단계 메뉴: `tkvf75`, `dwf75` (2026-11-15 10:20 시작, 12:15 축소)

- **왜.** 4.5 를 보고 본 평가를 메뉴 150~400 간격 50 으로 다시 돌리려 했다. 이때 거친 메뉴의 시드 2·3 추가를 멈췄다.
- **사용자 결정으로 축소.** 용량 단계는 근사가 아니라 인스턴스의 일부이고, 메뉴를 바꾸는 것은 민감도로만 본다. 더 촘촘하게 파지 않는다.
- **상태.** 지리 7~8 개 (g1~g8 일부) 만 돌리고 새 투입을 멈췄다. 결과는 "메뉴를 바꿔도 결론이 같은가" 확인용이다.
- **주의.** 이 설정은 층화 후보 수가 구간당 2 (본 구성은 3) 다.

### 4.9 모형 점검과 용량비 선별: `expo13`, `expo14` (2026-11-15 저녁)

- **경위.** 사용자 요청으로 실험을 멈추고 모형부터 다시 봤다 (가설 문서 9 절). 결론: B 는 늘 거의 다 팔려서 리더 판매가 약정량과 용량 사이 좁은 폭에 갇히고, 그래서 진짜 분포를 모르는 것의 직접 손해가 거의 없다.
- **왜.** 리더가 수요 위험을 지게 하는 손잡이는 용량 선택지가 아니라 용량비다 (리더는 한 단위가 전체 시나리오의 $1 - 0.6(1 - c/v)$ 이상에서 팔릴 때만 짓는다). 용량비 0.2 에서 판매 폭과 직접 손해가 실제로 커지는지 본다.
- **무엇을 바꿨나.** 용량 메뉴 200·300·400·500 (상한 400 → 500), 예약 상한 300 → 500 (`expo13`). `expo14` 는 예약 상한만 300 으로 두어 상한의 효과를 따로 본다. 예약료 0.75, 용량비 0.5·0.4·0.2 모두 출력.
- **어떻게.** 지리 g1~4 × 시드 1, 결정 19,604 개 전수 열거. 스크립트 `expoR.jl` (= `expo.jl` + 직접 경로 손해: 진짜 분포 시험 표본 500 개, 소매상 belief = 리더의 추정, Nominal 대 상위 30 개 + 총 용량별 최선 + Data-DR 결정). 선별이지 본 평가가 아니다.
- **예측.** `cf_predictions.txt` H56.
- **상태.** 끝 (18:00, 8 건, 로그 `expo_run4.log`).
- **결과.** 용량비 0.2·예약 상한 500 에서 판매 폭 평균 17% (지리별 7, 38, 23, 2), 직접 손해 2.6% (0, 10.1, 0.2, 0), Data-DR 이 그만큼 이김. 용량비 0.5 는 직접 손해 0.04%. 지리 한 곳이 끌고 간 결과라 방향만 확인. 예약 상한 300 은 판매 폭을 억지로 만든다 (23~38%). 표는 가설 문서 9.4.

- **확대 (18:20, 사용자 승인).** 같은 두 설정을 지리 g5~15 에 추가 (22 건, 로그 `expo_run5.log`). 물음: g2 같은 경우가 15 곳 중 몇 곳인가. 예측 H57. 상태: 끝 (19:20). 결과: 예약 상한 500·용량비 0.2 에서 판매 폭 16% 인데 직접 손해 ≥ 1% 는 2/15 (중앙값 0.2%), 기각 조건 해당. g2 는 예외. belief 노출은 안 줄음 (10.2). 예약 상한 300 은 7/15. 표는 가설 문서 9.6.

- **정정 (2026-11-15 밤).** 위 판정 (용량비만 내려서는 Data-DR 값어치 없음) 은 철회. 손해가 운 나쁜 표본에 몰려 있는 꼬리 현상인데 빈도와 평균으로 판정했음. 새 실행 없이 같은 30 건을 다시 읽은 것. 가설 문서 9.7 절.

### 4.21 상자 폭을 균등 확률에 비례하게: 설정 `dwpb2`, 스크립트 `dwLeanB.jl` (2026-11-17 오후, 사용자 방향: ε 한 개로 조절, TV 볼은 살림)

- **왜.** 지금 집합은 TV(q̂, ε) ∩ 상자 (폭 2ε/√S). S = 10 에서 균등 확률은 0.10 인데 ε = 0.3 의 상자 폭은 0.19 라 거의 묶이지 않는다. 리더 CVaR (β = 0.4, 꼬리 0.6) 의 최악 분포가 꼬리 무게의 83% 를 최악 두 시나리오에 싣는다 (Nominal 33%). Data-DR (0.3) 이 약정 수준 가까이로 용량을 줄이는 원인이다 (가설 문서 9.18 보충). 상자 폭이 1/√S 로 줄고 확률은 1/S 로 줄어 S 가 클수록 더 느슨해진다.
- **무엇을.** 상자 폭을 2tε·q̂_k 로 둔다 (t 는 고정 상수, 조절은 ε 하나). 지금 집합은 t = √S 인 경우다. t = 1 은 TV 제약이 저절로 성립해 상자만 남으므로 쓰지 않는다 (사용자: TV 볼은 살려야 함). **t = 2** 로 시험한다 (옮긴 확률을 시나리오의 4 분의 1 이상이 나눠 받음). 최악 두 시나리오의 꼬리 무게 (LP 로 검산): t = √S 에서 ε 0.1·0.2·0.3 이 50·67·83%, t = 2 에서 47·60·73%, t = 1.5 에서 43·53·63%, t = 1 에서 40·47·53%.
  - 데이터 집합 (Data-DR): `SC_BOXT=2`. `worst()` 의 상자 폭만 바뀜.
  - belief 집합 (Belief-only): `SC_BOXTB=2`. 지금까지 belief 볼은 상자 없는 TV 볼이었다 (δ = 0.1 이면 한 시나리오를 0 으로, 다른 하나를 두 배로 하는 꼭짓점 90 개). 같은 규칙을 적용하면 δ = 0.1 에서 폭 0.04 (세 시나리오에서 0.04·0.04·0.02 를 빼 세 시나리오에 준다). 꼭짓점이 많아 무작위 150 개 + 내부 방향 20 개로 근사한다 (최악을 놓칠 수 있음).
  - Nominal 은 그대로. Data-DR 은 데이터 집합에만, Belief-only 는 belief 집합에만 의존하므로 한 번의 실행으로 두 효과를 따로 볼 수 있다. 나머지 설정은 `dwpl75` 와 같다 (가격 기준, 선구매가 비율 0.75, 메뉴 200·300·400).
- **어떻게.** `dwLeanB_job.sh dwpb2 <g> <s>`, 목록 `dwB_list.txt` (150 건), 로그 `dwB_run.log`, 출력 `geo/dw/{vn,dw,sel}_dwpb2_g<g>_s<s>.csv`. 끝나면 `zsW_job.sh` 를 `ZS_ENVCFG=dwpb2` 로 돌려 γ·ζ 격자 (γ 0.1~10) 에서 평가. 예측 H67. γ = 3·10 실행 (4.20) 이 끝난 뒤 시작.
- **모형의 집합 (2026-11-17 오후, 사용자가 바로잡음. 이 항목의 앞 서술 중 belief 상자에 관한 부분은 이것으로 대체).** 리더는 집합 둘을 잡는다. 수요 분포 a ∈ TV(q̂, ε̂) ∩ 상자(ε̂), 소매상 belief d ∈ TV(q̂, ε̃) ∩ 상자(ε̃). 둘 다 q̂ 기준이다. 그리고 둘을 TV(a, d) ≤ δ 로 묶는다. 상자는 ε 에 딸린 것이고 δ 에는 상자가 없다.
  - Belief-only (ε̂ = 0, ε̃ = 0.3, δ = 0.1): a = q̂ 이므로 d ∈ TV(q̂, 0.1) ∩ 상자(0.3). 상자 폭은 옛 규칙 0.19, 새 규칙 (t = 2) 0.12 인데 TV 0.1 안에서는 한 시나리오가 0.1 넘게 변할 수 없어 상자가 묶이지 않는다. 따라서 스크립트의 Belief-only (TV 볼만) 는 두 규칙 모두에서 모형과 같다. **지금까지의 Belief-only 결과는 그대로 유효하고 새 규칙에서도 바뀌지 않는다.**
  - 내가 넣었던 `SC_BOXTB=2` 는 상자를 δ 에 딸리게 한 것 (폭 4δ·q̂ = 0.04) 이라 모형과 다르다. 대기열이 시작되기 전에 설정 `dwpb2` 에서 `SC_BOXTB=0` 으로 고쳤다 (13:46). 그 옵션으로 돈 시험 한 건 (g1 s1) 의 출력은 `*_dwpb2_g1_s1.boxtb2_test.*` 로 이름을 바꿔 두었고 쓰지 않는다.
  - 이 실행에서 바뀌는 것은 Data-DR (데이터 집합의 상자 폭) 뿐이다. Coupled 를 풀 때는 belief 상자도 q̂ 기준, 폭 4ε̃·q̂ 로 둔다 (a 기준이 아님).
- **범위.** 입지 가치 실험에서만 시험한다. 집합 정의를 두 게임과 계산 표에 적용할지는 결과를 보고 사용자가 정한다. 저장소 코드는 바꾸지 않았다.
- **상태.** 대기열에 걸어 둠.

- **이전 결과와의 관계.** 지금까지의 Belief-only (δ 0.1, 상자 없는 TV 볼 0.1) 는 새 정의로는 "반지름 0.1, 상자 없음" 에 해당한다. 새 Belief-only (0.1) 은 같은 반지름에 상자 (폭 0.04) 가 더해져 더 순하다.

### 4.25 "수요를 헤징하되 소매상 belief 가 진짜를 따라가는" 모형과 Data-DR 의 비교: `dtrackW.jl` (2026-11-17 저녁, 사용자 제안)

- **왜.** Data-DR 은 수요 분포만 움직이고 소매상 belief 는 q̂ 에 고정한다. 사용자 가설: belief 를 q̂ 로 넣는 것이 의도치 않게 보수적인 쪽으로 간다. 내 설명은 반대 (q̂ 고정은 저수요 방향에서 낙관적, 가설 문서 9.18). 지금까지의 근거는 진짜 분포 하나에 대한 간접 비교뿐이라, 집합 전체의 최악을 보는 모형끼리 직접 비교한다.
- **무엇을.** 같은 집합 U(r) (TV 볼 ∩ 상자, 폭 r/√S) 에서 두 값을 견준다.
  - Data-DR: V_D(x) = max_{a ∈ U(r)} J(x; a, q̂).

### 4.29 소매상이 주문을 버릴 수 있게: 판매가 r 하나 (2026-11-17 밤, 사용자 제안. 준비만 하고 본 실행은 Coupled 결과를 본 뒤 결정)

- **왜.** 지금은 수요를 반드시 채워야 해서 고객이 아무리 멀어도 가장 가까운 열린 거점에서 산다. 그래서 리더 점포 하나가 여러 지역에 팔고 리더 수입이 총수요를 따라가며, Data-DR 의 대비가 "총수요가 낮은 시나리오를 보고 여유 용량을 줄인다" 한 방향이다 (가설 문서 9.21 보충 3~7, 9.23). 먼 주문을 버릴 수 있으면 거점마다 닿는 범위가 생기고 리더 점포의 수입이 주변 수요를 따라간다 (사용자: 수송을 막거나 수송비를 크게 올리면 알아서 버린다).
- **무엇을.** 소매상의 2 단계 문제에 안 채운 수요 $u_j \ge 0$ 을 넣는다. 수요 제약은 $\sum_i (y^R_{ij} + y^S_{ij}) + u_j \ge \xi_j$, 소매상의 비용에 $r\,u_j$ 가 더해진다. $r$ 은 소매상이 고객에게 한 단위를 팔아 받는 값이다 (사용자 결정: 거리 한도나 비선형 수송비를 따로 두지 않고 r 하나로). 소매상은 산 값 + 수송비가 $r$ 보다 크면 버린다. 추가 주문은 거리 $r - p$ 까지, 약정분은 $r - f$ 까지 닿는다 ($p = 800$, $f = 600$). 리더의 손실 식은 그대로다 (안 채운 수요에서 리더가 얻는 것은 없음). $r$ 의 값은 정하지 않았다. 시험은 $r = 1400$ (추가 주문 600, 약정분 800 까지. 고객에서 같은 지역 거점까지 평균 620, 다른 지역 1756).
- **어떻게.** 스크립트 `dwLeanR.jl` (= `dwLeanN.jl` 에 `with_shortage` 를 얹은 사본, 환경변수 `SC_R`, 0 이면 기존과 같음), 작업 `dwLeanR_job.sh`. 저장소 코드와 기존 스크립트는 건드리지 않는다. 예전에 기각된 외부 현물시장 (거점의 추가 주문을 없앰) 과는 다르다. 거점의 추가 주문은 그대로다.
