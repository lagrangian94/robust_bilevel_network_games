## 1. 왜 B&P 인가

| 방법 | 마스터 하한 | 문제 |
|---|---|---|
| 명시 판 (블록을 마스터에 통째로) | MILP 의 LP 완화 (높은점 수준) | B&B 노드 2\|X\| − 1, 열거 |
| 한 나무 판 (블록 = LP cut) | 같은 LP 완화의 접평면 | 정수 후보 = \|X\| (8,464), 열거 |
| DW 루트 (블록별 볼록 포락) | Farley 하한 | 블록별로 따로 볼록화해서 생기는 간격이 belief 에 따라 0.28% ~ 1.3% |
| **DW + 분기 (B&P)** | 노드마다 Farley 하한 | 이번 문서 |

- CCG 는 마스터를 정확히 풀 필요가 없고, 유효한 하한이 허용오차 안에만 있으면 된다.
- 휴리스틱 마스터만으로는 안 된다. x̄ 가 마스터 최적이 아니면 같은 x̄ 와 belief 만 맴돌 수 있으니, 하한을 따로 증명해야 한다.
- DW 루트만으로는 간격이 허용오차를 넘는 경우가 있다 (`ccgdw_v2.jl`, 지리 1: belief 14 개에서 0.65%, 상태 DWGap).
- DW 로 하한을 내고 마무리를 lazy cut 나무로 하면 (`ccgdw_v3_hybrid.jl`) 나무가 다시 정수 후보 8,056 개를 훑는다 (전체 1,901 s). 사용자 지적대로 이것은 전수조사에 기대는 것이라 버렸다.

## 2. 알고리즘 (`ccgbp.jl`)

**마스터의 DW.** 블록마다 λ^b (열 = X 의 점 z, 비용 L_b(z) = 블록 LP 하나), x 는 블록들이 공유. 안전장치 (no-good, restricted cut) 는 아핀 블록으로 넣는다 (가격이 선형이라 탐욕으로 정확).

**1 단계 (루트, belief 모으기).** 휴리스틱 열 생성 (가격 MILP 없음) → 마스터 UB 점들에서 싼 belief 탐색 → 없으면 마스터 UB 점에서 oracle (α-B&B) → belief 추가 → 반복. oracle 이 진전을 못 주면 2 단계로.

**2 단계 (B&P).**
- 노드 = 고정 (x_jk = 0, x_jk = 1, 거점 j 개설 강제). 열과 열 풀은 노드 사이에 공유하고, 노드에서는 맞는 열만 쓴다.
- 노드 처리: 휴리스틱 열 생성 → 탐색 (belief 가 늘면 다시) → RMP 값이 UB − tol 이상이거나 x̃ 가 정수일 때만 정확 가격 (가격 MILP, Farley 하한).
  RMP 값이 UB − tol 보다 낮으면 증명해도 못 자르므로 가격 MILP 없이 바로 분기한다.
- 분기 규칙:
  1. 거점 개설 o_j = Σ_k x_jk 가 분수인 거점 중 가장 분수인 3 개를 후보로, 두 자식을 휴리스틱 열 생성으로만 풀어 (v₁ − v)(v₀ − v) 가 가장 큰 것을 고른다 (strong branching).
  2. 개설은 모두 정수인데 크기가 분수면 x_jk 로.
- 노드 선택: 증명된 하한, 그다음 strong branching 추정치 순 (best-first).
- 가지치기: 노드 하한 ≥ UB − tol·|UB|.
- 정수 노드: 그 점에서 oracle (마스터 값이 지난 확인 때보다 올랐을 때만).
- oracle 목표는 지금 LB 기준 (LB + 0.95 tol − q): 끝에 UB − LB ≤ tol 이 되게.

**DW 에서만 생기는 성질.** 블록의 μ 를 크게 잡아도 마스터가 약해지지 않는다. DW 는 정수점의 블록 값만 쓰고 cut 의 기울기를 쓰지 않기 때문이다. 그래서 μ = 1,000 으로 시작해 μ 올림 (블록 재구성) 을 없앴다 (지리 1: 14 회 → 0 회).
이것은 속도 조정으로는 맞았지만, η = 0.1 과 함께 쓰면 블록이 μ → ∞ 쪽에 가까워져 과대평가가 커질 수 있다. 7 절의 단서를 보라.

## 5.1 v5: 인증용 설정 (η, μ, λᵁ) = (10⁻⁴, 10⁴, 10⁴)

  저장소 oracle 은 고치지 않았다 (허락 필요). 후보는 λᵁ = 10⁴ 에서 α-B&B 의 LP·Ipopt 수치를 점검하는 것, 또는 δ-최적 follower 로 λᵁ 를 명시적으로 잡는 것이다 (7 절).
- 평가한 점의 비율이 v4 보다 올랐다 (지리 10: 12% → 60%). 블록 값이 바뀌어 휴리스틱 이웃이 더 돌았다. "열거하지 않는다" 를 보이려면 |X| 를 키운 실험이 필요하다 (예: N_B = 4 면 |X| ≈ 66,000, 지금의 8 배).

### 5.2 oracle 수정 (저장소 `nz_alpha_bnb.jl`, `nz_alpha_bnb_dr.jl`, 2026-11-23 사용자 허락)

**원인.** 실패는 α 고정 LP (`nz_eval_alpha!`, B&B 노드의 α̂ 를 정확히 평가하는 LP) 에서 났다. `NZ_NUMERR_DUMP` 로 실패 LP 셋을 덤프하니
행렬 계수 범위 4×10⁻⁶ ~ 2×10⁵, 목적 계수 범위 0.7 ~ 4×10⁷ (λᵁ = 10⁴ 가 벌점항에 곱해진 크기) 였고, **새로 풀면 셋 다 OPTIMAL** 이었다 (NumericFocus 3, Method 1·2 도 OPTIMAL).
LP 는 유계인데, α̂ 계수만 바꿔 이전 기저에서 이어 푼 dual simplex 가 비유계로 오판했다. 기존 재시도 경로는 기저를 버리는 새 풀이를 한 번만 하고, 이어지는 NumericFocus 3 재시도는 기저를 남긴 채 풀어 같은 오판을 되풀이했다.
같은 점에서 oracle 만 따로 돌리면 (지리 12, λᵁ = 10⁴) 수치 오류가 나도 재시도로 복구되어 510 s 에 끝났다 (V ∈ [−3,140.97, −3,140.66]). 실패는 α̂ 순서와 스레드 타이밍에 따라 갈리는 간헐적인 것이다.
λᵁ = 100 에서도 같은 오판이 한 번 기록되어 있다 (코드 주석, 2026-11-20, loc_tkp 지리 1, 재시도로 복구). λ 가 작으면 드물 뿐 없어지지 않는다.

**고친 것.**
1. 재시도 (NumericFocus 3, Method 1·2) 마다 `GRBreset` 으로 기저를 버리고 처음부터 푼다. 재시도 뒤에도 비유계면 지금처럼 오류를 낸다 (오류 처리를 약하게 하지 않음).
2. 정확 평가용 α̂ 사본에서 10⁻⁶·max(1, hᵁ) 미만 성분을 0 으로 정리한다 (나무 판 `exact_value` 와 같은 처리). W ≥ 0 이라 H 안에 남고, 값은 그 점에서 정확히 평가하므로 incumbent 로 유효하다.
   α̂ 자체 (곱 위반, 분기점, 완화 값의 귀속) 는 그대로 둔다.

**확인.** v5 를 지리 9·12 에 다시 돌림 (`bp5fix_g9.log`, `bp5fix_g12.log`): 비유계 보고 7 번이 모두 재시도로 OPTIMAL 이 되었고, 두 지리 모두 Optimal 로 끝났다. 그래서 v5 (λᵁ = 10⁴) 는 지리 7 개를 모두 끝낸다.

## 6. μ 와 η 가 코드에 들어가는 곳 (`nz_belief_ccg.jl` `_bccg_add_block!`)

- μ 는 블록의 행 하나 `t0 ≥ μ (C_F − η C_L⁺) + C_L + μ · dobj` 에만 계수로 들어간다. 그래서 생성기를 다시 짓지 않고 그 행의 계수만 바꿔 제자리에서 갱신할 수 있다.
  지금 시험판은 μ 를 올릴 때 생성기를 통째로 다시 짓는다 (스레드마다 사본 12 개, v1 에서 202 s). 제자리 갱신으로 바꿀 여지가 있다.
- η 는 쌍대 제약의 우변 (`_bccg_ceta` = d_s c_j + η r_s ℓ_j) 과 McCormick 상한 U (d_s π_F^U + η r_s max|ℓ|) 에도 들어간다. 바꾸려면 우변과 상한도 고쳐야 한다.
- oracle 의 λᵁ 는 `loc_tkp.jl` 의 기본값 `lambdaU = 100.0` 이다. 시험판은 oracle 을 나무 판과 같게 부르므로 같은 값이다.

## 7. 유효성 단서: η = 0.1 은 η̄_b 를 넘는다 (사이드 대화 2026-11-23 의 측정)

원고 Proposition (Belief blocks) 의 유효성 L_b ≤ V_b 는 η ≤ η̄_b 에서만 성립한다. 지리 1 전체 X × 최종 belief 11 개에서 정확한 pessimistic 값과 비교한 측정은 다음과 같다.

| 설정 | 정확값보다 큰 점 (belief 마다) | 최대 차이 |
|---|---|---|
| 지금 블록 (η 0.1, μ → ∞) | 명목 belief 0, 나머지 169 ~ 792 | 127 |
| η 0.01, μ → ∞ | 13 ~ 147 | 126 |
| V^λ, λ = 100 | 명목 0, 나머지 5 ~ 134 | 99 |
| V^λ, λ = 1,000 | belief 두 개만 (6 점, 11 점) | 15.6 |
| V^λ, λ = 10,000 | 0 | 10⁻⁵ |

- 블록이 V* 보다 크면 그 블록의 하한 (Farley, 노드 가지치기, 나무 판의 cut) 은 무효다. 그래서 3·4 절의 "Optimal" 은 하한이 인증되지 않은 결과로 읽어야 한다. 지금 솔버의 결과 (`nz_belief_block_ccg.md` 13 절) 도 같다.
- 정확한 pessimistic 블록으로 다시 계산하면 같은 belief 들에서 X 위 최소가 −1,633.04 이고, CCG 의 답 −1,629.42 와 0.22% 차이라 지리 1 은 허용오차 안에 운 좋게 들어 있었다. 다른 지리는 모른다.
- **고치는 방향.** 섭동 follower 의 argmin (C_F − η C_L) 은 비최적성을 비율 1/η 로 벌하는 것과 같다. 블록을 η = 1/λ, μ = λ 로 묶으면 C_L 항이 소거되어 L_b = V_b^λ (원고 Prop (certificate) (ii) 의 벌점값을 belief b 로 제한한 것) 가 된다.
  그러면 따로 정의한 η̄_b (계산 수단 없음) 가 필요 없고, 블록과 oracle 이 같은 V*_{λᵁ} 를 푼다. 지리 1 에서 λ̄ 는 1,000 과 10,000 사이였다. oracle 의 λᵁ = 100 도 이 인스턴스에서는 부족하다.
- **다음 실행 설정.** (η, μ, λᵁ) = (10⁻⁴, 10⁴, 10⁴), μ 는 더 올리지 않는다 (x̄ 에서 블록이 부족하면 바로 no-good).

**μ 와 λ 를 도중에 바꿀 수 있는가.**
- η 를 따로 고정한 원래 블록 (η ≤ η̄ 아래) 에서는 L_b 가 μ 에 대해 단조 증가하고 모든 μ 에서 하한이라, 작게 시작해 올려도 이미 증명한 하한이 유지된다.
- η = 1/λ, μ = λ 로 묶은 블록 V_b^λ 는 λ 에 대해 단조 감소하고 λ < λ̄ 이면 V* 를 과대평가한다. 그래서 λ 는 처음부터 충분히 크게 두고 사후에 λ ≥ λ̄ 를 인증해야 한다. 도중에 바꾸면 이미 친 가지가 무효가 될 수 있다.
- oracle 의 UB 는 어떤 λ 에서도 유효하다 (Corollary conservative). λ 가 영향을 주는 것은 하한 쪽뿐이다.
- δ-최적 follower (원고 Remark near-optimal follower) 를 쓰면 λᵁ ≥ LD/δ 와 η ≤ δ/R, η < p̃_min/θ̄ 로 상수를 명시적으로 잡을 수 있다. δ 를 작게 잡을수록 λᵁ 가 커지는데, 그 큰 벌점을 감당하는 쪽이 DW 라는 논거와 맞물린다.

**DW 가 큰 벌점에 유리한 이유와 아직 모르는 것.**
- 구조: DW 는 정수점의 블록 값만 쓰고, 벌점에 비례해 가팔라지는 cut 기울기를 쓰지 않는다. μ = 10⁴ 은 Benders 나무에는 치명적이다 (cut 기울기 ∝ μ × 용량 × U).
- 확인 안 됨: μ = λ = 10⁴ 에서 가격 MILP 와 블록 LP 의 수치 (계수 범위, η = 10⁻⁴ 가 follower 비용 규모 10⁶ 에서 LP 허용오차에 가까움, 비용 차이가 상대 10⁻⁸ 인데 리더 손실이 36 만큼 갈리는 무차별점).

**남는 인증 문제 (원고).** 원고의 λᵁ 사후 인증은 모든 x ∈ X 에서 확인하므로 |X| = 8,464 에서는 그 자체가 열거다. B&P 에서 인증을 "가지치기에 쓴 노드들" 로 줄일 수 있는지는 아직 생각하지 않았다.

## 10. B&P 절차 (기본 판 v6, 2026-11-23 확정)

`docs/nz_ccg_bnp_scripts/ccgbp.jl`. 저장소의 블록 생성기, belief 탐색, α-B&B oracle, 확보 규칙을 그대로 부르고, 마스터만 DW branch-and-price 로 푼다.

### 10.1 대상과 상수

- **마스터 M(𝒞, 𝒢).** min_{x∈X} qᵀx + t, t ≥ L_b(x) (belief b ∈ 𝒞), t ≥ a_g + c_gᵀx (안전장치 g ∈ 𝒢: no-good, restricted ISP cut).
- **블록 L_b.** belief b 를 고정한 LP 이고, 정수 x 에서 값이 정확하다. η = 1/λᵁ, μ = λᵁ 로 묶어 원고 Prop (certificate) (ii) 의 벌점값을 b 로 제한한 것 (V_b^λ) 과 같게 둔다.
- **상수 (기본값).** λᵁ = μ = μ 상한 = 1/η = 10⁴, oracle 도 같은 λᵁ. θᵁ 는 순환 열거로 구한 인스턴스 값. 허용오차 tol = 0.5%.
- **X 는 나열하지 않는다.** 점은 만났을 때만 번호를 붙인다 (정렬한 활성 성분을 키로).

### 10.2 마스터의 DW 재정식

- 블록 b 마다 볼록결합 λ^b (열 = X 의 점 z, 비용 = 블록 LP 값 L_b(z)), x 는 블록들이 공유한다.
  RMP: min qᵀx + t, t ≥ Σ_z λ^b_z L_b(z), Σ_z λ^b_z z = x, Σ_z λ^b_z = 1 (블록마다).
- 안전장치는 아핀 블록으로 같이 넣는다. 값이 z 의 선형식이라 가격이 탐욕으로 정확하다.
- RMP 는 barrier, crossover 끔으로 풀어 중심 쌍대를 얻는다 (퇴화 진동 방지). 수치로 멈추면 crossover, 그다음 dual simplex 로 다시 푼다 (Farley 하한에 정확한 쌍대 실행가능성이 필요).
- **Farley 하한.** 쌍대 (w, π, σ) 에서 LB = RMP + Σ_b min(0, min_z [w_b L_b(z) − π_bᵀz] − σ_b). 임의의 쌍대 실행가능 점에서 유효하다.

### 10.3 노드에서의 열 생성 CG(n)

노드 n = (x_jk = 0 집합, x_jk = 1 집합, 개설을 강제한 거점 집합). 열과 열 풀은 노드 사이에 공유하고, 노드에서는 고정과 맞는 열만 쓴다.

1. 노드와 맞는 정수점 하나를 모든 블록에 넣는다 (RMP 실행가능).
2. RMP 를 풀어 쌍대와 지지 열을 얻는다.
3. **휴리스틱 가격** (가격 MILP 없음).
   - w_b > 0 인 belief 블록: 지지 열의 이웃 (거점 하나 빼기·더하기·옮기기·크기 바꾸기 중 노드와 맞는 것, 지지 열당 표본 10 개) 과 값을 아는 열 풀의 점을 블록 LP 로 평가하고, 환원비용이 가장 작은 점을 넣는다.
   - w_b = 0 인 블록과 아핀 블록: 환원비용이 z 의 선형식이라 노드 위 X 에서 탐욕으로 정확히 푼다.
   - 새 열이 있으면 2 로.
4. 새 열이 없으면 지지 열을 모든 블록으로 평가해 **정수 후보** (열 중 마스터 값 qᵀz + max_b L_b(z) 가 가장 작은 점) 를 고친다.
5. **정확 가격** (하한이 필요할 때만). w_b > 0 인 belief 블록마다 가격 MILP min_z w_b L_b(z) − π_bᵀz (블록 + 이진 z + 노드 고정, IntFeasTol 1e-9) 를 푼다.
   - 멈춤 기준은 가지치기에 필요한 여유 (RMP − (UB − tol)) 를 블록 수로 나눈 값이다 (최소 10⁻⁴·|RMP|). 하한은 MILP 가 증명한 bound 를 쓰므로 일찍 멈춰도 유효하다.
   - MILP 해 풀의 열 중 환원비용이 음인 것을 넣고 2 로.
6. 끝: Farley 하한 ≥ UB − tol (노드를 자를 수 있음), 또는 새 열이 없음, 또는 하한이 정수 후보 값의 0.1% 안.

### 10.4 1 단계: 루트에서 belief 모으기

반복한다.
1. CG(루트) 를 휴리스틱 가격만으로 푼다.
2. 마스터 값이 좋은 정수점 5 개에서 싼 belief 탐색을 한다 (지금 belief, 원소 쌍 이동, 무작위 40 개 → 국소 개선). 마스터 값보다 큰 값을 주는 belief 가 있으면 넣고 (10.6) 1 로.
3. 없으면 정수 후보에서 oracle (α-B&B, 호출당 900 s 상한) 을 부른다. belief 나 no-good 이 늘면 1 로, 아니면 2 단계로.

### 10.5 2 단계: branch-and-price

- **노드 선택.** 증명된 하한이 가장 작은 노드, 같으면 strong branching 추정치가 작은 노드.
- **노드 처리.**
  1. CG(n) 휴리스틱 → 마스터 값이 UB − tol 보다 낮은 정수점에서만 belief 탐색 (그 위의 점에 belief 를 더해도 가지치기가 바뀌지 않음). belief 가 늘면 다시.
  2. RMP 값이 UB − tol 이상이거나 x̃ 가 정수면 정확 CG 로 Farley 하한을 낸다. RMP 값이 UB − tol 보다 낮으면 증명해도 못 자르므로 바로 분기한다.
  3. 마스터 incumbent 가 UB 를 고칠 수 있고 그 점의 마스터 값이 지난 oracle 확인 뒤 올랐으면 oracle 을 부른다. belief 가 늘면 이 노드를 다시 연다.
  4. 하한 ≥ UB − tol 이면 자른다.
  5. x̃ 가 정수면 그 점에서 (필요하면) oracle 을 부르고, 노드를 닫힌 노드로 남긴다. 닫힌 노드의 하한 = max(노드 하한, 그 점의 마스터 값, q + oracle 하한).
  6. 아니면 분기한다.
- **분기 규칙.**
  1. 거점 개설 o_j = Σ_k x_jk 가 분수인 거점 중 가장 분수인 3 개를 후보로, 두 자식 (o_j = 1 은 그 거점의 단계 중 하나를 강제, o_j = 0 은 그 거점의 모든 x_jk = 0) 을 휴리스틱 CG 로만 풀어 (v₁ − v)(v₀ − v) 가 가장 큰 후보를 고른다 (strong branching).
  2. 개설이 모두 정수인데 크기 x_jk 가 분수면 가장 분수인 x_jk 로 분기한다.
  3. 정수 노드에서는 모든 블록의 λ^b 가 그 점 하나에 모인다 (정수 x 는 conv X 의 꼭짓점). 그래서 노드 값이 마스터 값과 같다.
- **종료.** 열린 노드가 없으면 LB = min(UB − tol, 닫힌 노드의 하한) 이다. UB − LB ≤ tol 이면 Optimal.
  닫힌 노드가 종료를 막으면 그 점의 oracle 을 상한 2 배로 다시 부르고, belief 가 늘면 그 노드를 다시 연다.

### 10.6 belief 확보와 oracle

- **확보.** 새 belief 블록이 x̄ 에서 oracle (또는 탐색) 값 v 이상이면 끝. μ 가 이미 상한이라 올리지 않고, 모자라면 no-good t ≥ v − (v − t_low)·Hamming(x, x̄) 를 넣는다. t_low = 명목 블록의 X 위 최소 (가격 MILP 로 한 번).
- **oracle 결과 처리.** UB 는 oracle 의 상한으로 고친다 (어떤 λ 에서도 유효). oracle 이 t₀ 보다 큰 하한을 냈으면 그 α 의 정확 평가로 belief 를 만든다. 평가가 실패하면 그 하한으로 no-good, 진전이 없으면 restricted ISP cut 을 넣는다.
- **oracle 목표.** τ = max(t₀, LB + 0.95·tol·|LB| − qᵀx̄) (LB 가 없으면 t₀ + 0.9·tol). 끝에 UB − LB ≤ tol 이 되게 하는 값이다.
- **oracle 수치.** α 고정 LP 의 재시도마다 기저를 버리고 처음부터 푼다 (저장소 42f46dc, 5.2 절).

### 10.7 유효성과 남는 단서

- UB 는 oracle 이 주므로 어떤 상수에서도 유효하다.
- LB (Farley, 노드 가지치기) 는 블록 ≤ V* 일 때 유효하다. μη = 1 묶음에서는 λᵁ ≥ λ̄ 이면 성립한다. **λᵁ ≥ λ̄ 의 사후 인증은 아직 하지 않았다** (원고 방식은 모든 x 에서 확인이라 |X| 가 크면 그 자체가 열거다).
- 정수 노드를 닫을 때 그 하한을 전역 LB 에 남기므로, oracle 이 결론 없이 끝난 점도 LB 를 잘못 올리지 않는다.

### 10.8 기록하는 지표

블록 LP 로 평가한 점, 번호를 붙인 점, RMP 에 들어간 열 (블록 합, 서로 다른 열), 가격 MILP 호출과 Gurobi 노드, B&P 노드 (잘림, 정확, 정수, 닫힘), oracle 호출과 시간, 안전장치 수.
열거하지 않는다는 근거로는 RMP 열 수와 가격 MILP 노드를 쓴다 (평가한 점의 비율은 휴리스틱 설계의 숫자).

- incumbent 가 마스터가 아는 값보다 나쁘다 (S = 20 지리 1: α-B&B incumbent −3,462, 마스터 블록 값 t0 = −3,445.17 은 V* 의 유효한 하한). 목표 τ 는 종료 조건에만 쓰인다. 둘 다 처음엔 개선 후보로 봤으나 best-first 에서는 효과가 작다 (11.4).

**2·3 의 효과는 작다 (2026-11-24 정정).** α-B&B 는 상한이 가장 큰 노드부터 꺼낸다 (best-first, `popat!(open, argmax(ub))`, + dive 최대 3).
그래서 상한 ≤ τ 인 노드는 τ 위의 노드가 다 없어진 뒤에야 차례가 오는데, 그때는 UB ≤ τ 로 이미 끝난다. 두 후보가 줄이는 것은 dive 로 처리하는 자식 노드뿐이다.
S = 10 재현 (지리 1, {9:200;10:300;15:300}): 386 s 에 목표 도달로 끝났고 남은 열린 노드 535 개는 모두 상한 ≤ τ (종료 조건상 당연).
인증 (결과 b) 시간을 정하는 것은 완화 상한의 세기와 분기다.

**그러나 위반 발견 (결과 a) 에는 incumbent 가 결정적이다 (resp 시험, 2026-11-24).** S = 20 지리 1 의 막힌 호출 ({9:200;10:300;15:200}, 목표 −3,437.59):

| 설정 | 시간 | 노드 | 끝난 상태 |
|---|---|---|---|
| 기본 (resp 끔) | 3,605 s (상한) | 7,877 | V ∈ [−3,461.74, −3,378.28], incumbent 가 t0 = −3,445.17 아래 → 결론 없음 |
| `resp=true` | **206 s** | 219 | incumbent −3,411.29 ≥ 목표 → **위반 발견** (이 점의 참값 > 마스터 값, 새 belief) |
| 노드 LP barrier (`lp_method=2, lp_crossover=0`) | 211 s | 1 | 루트 Ipopt 한 번이 −3,433.60 → 위반 발견 (루트 LP 190 s, 수치 오류 9) |
| `child_rounds=3` | 1,805 s (상한) | 3,560 | UB −3,327.03 (기본 1,813 s 에 −3,331.35 와 같음), incumbent −3,467.47 → 결론 없음 |
| 범위 MIP (`range_lp=false`) | 1,783 s | 1 | 루트 범위 MIP 340 개에 1,759 s, 루트 Ipopt 한 번이 −3,433.55 → 위반 발견 |

- barrier·범위 MIP 는 노드 처리가 빨라서가 아니라 **루트 LP 해가 달라 Ipopt 시작점이 바뀌어** 좋은 α 에 닿았다 (기본은 Ipopt 61 번에도 −3,461.7 이 최선). 국소 탐색이 시작점에 매우 민감하다는 해석 (직접 검증은 안 함).
- 그래서 S = 20 에서 고칠 곳은 (i) incumbent 휴리스틱 (resp, 여러 시작점), (ii) 노드 LP 비용 (82%) 과 필요한 노드 수 (인증 쪽) 둘이다. (i) 은 기존 옵션 resp 로 시험 (v8). (ii) 는 이번 ablation 의 기존 옵션으로는 개선이 없었다.

S = 20 에서 결론 없이 끝난 호출 상당수는 위반이 있었는데 α-B&B 의 incumbent 휴리스틱이 약해 못 찾은 것으로 보인다. 후보 2 (블록의 α 주입) 는 t0 를 넘지 못하므로 여전히 효과가 작다.
기본 판 시간 내역 (S = 20, 3,605 s): worker 시간의 82% 가 이완 LP (노드당 4.0 s, S = 10 은 0.64 s), 범위 10%, 평가 8%. 이 호출의 루트 상한은 −2,709 로 참값 −3,675 와 36% 떨어져 있고, 노드 4,103 개가 필요했다.

### 11.5 벌점 incumbent 는 정확값보다 낮다 (2026-11-24 밤, `exact_check.jl`)

oracle 의 하한 res[:LB] 는 벌점 Ω_λ 의 incumbent 값이다. incumbent α 가 꺾임점에서 1e-5 ~ 1e-3 벗어나 있으면 (예 α₉ = 199.999995, 꺾임점 200) follower 차이 벌점 λᵁ × (기울기) 가 붙어 값이 몇 단위 낮아진다 (기울기 ≈ 6 × 10⁵ / 단위).
같은 α 의 정확값 (`_bccg_value!`, α 를 belief 의 최적 반응으로 직접 평가) 과 비교:

| 호출 | 벌점 Ω incumbent | 정확값 |
|---|---|---|
| S = 10 지리 1 {9:200;10:300;15:300} | −3,682.19 | −3,678.27 |
| S = 20 지리 1 기본 | −3,461.74 | −3,457.28 |
| S = 20 지리 1 `child_rounds=3` | −3,467.47 | −3,441.77 |
| S = 10 지리 5 {4:200;7:200;12:300} | −3,156.50 | −3,156.50 (= t0) |

α 를 0.1 격자로 반올림하면 정확값과 같다 (반올림 자체는 필요 없음). 위반 판정을 정확값으로 하는 판이 `ccgbp_v9.jl` (11.8).
지리 5 는 벌점값 = 정확값 = t0 이라 이 점의 문제는 위반 발견이 아니라 **인증** (상한 ≤ τ) 이다.

### 11.6 h > b 상자와 HUCAP (oracle 정의역 h_i ≤ b_i(x̄))

남은 전선을 보면 (`front_stats.jl`) 연 B 거점의 약정 α_i 가 그 거점 용량 b_i(x̄) 를 넘는 상자가 안 잘리고 남는다.
S = 20 지리 1 은 열린 상자 1,888 개 중 240 개가 α₉ > 200 (거점 9 용량 200) 이고 상한 ≈ −3,379.6 (전선 최대 −3,378.3 근처), 75% 가 200 을 가로지른다. 지리 5 는 5,431 개 중 560 개.
약정 등식 Σ_j yR_ij + s_i = h_i 와 용량 행 Σ_j (yR_ij + yS_ij) + s_i ≤ b_i 에서 h_i > b_i 면 retailer recourse 가 실행 불가능하다.
벌점 정식에선 유한하지만 (λᵁ = 10⁴ 에서 단위당 약 1.45 × 10⁷) 완화가 그 벌점을 못 본다.

**HUCAP 은 연 B 거점의 hᵁ_i 를 b_i(x̄) 로 줄인다.** 이렇게 해도 상한 인증은 그대로 유효하다.
h_i > b_i 인 α 는 retailer 의 실행 가능한 1 단계가 아니어서 어떤 belief 의 최적 반응도 아니다. 그래서 줄인 정의역의 Ω_λ 도 최적 반응 α* (벌점 0) 를 품어 ≥ V*(x̄) 이다 (λ 와 무관하게 oracle 상한이 유효한 것과 같은 논증).
줄인 정의역의 α 는 원래 정의역에도 있으므로 하한 쪽도 그대로다. `nz_presolve_hU` (최적 반응이 늘 0 인 좌표 고정) 와 같은 종류의 정의역 축소다.

재현 (`orcl_replay.jl HUCAP=1`, 같은 점·같은 목표):

| 호출 | 기본 | HUCAP |
|---|---|---|
| S = 10 지리 1 {9:200;10:300;15:300} (resp 끔) | 386 s 인증, 노드 4,103 | **211 s 인증**, 노드 2,563 |
| S = 10 지리 5 {4:200;7:200;12:300} (resp) | UB 1,812 s −2,945 (6.7%), 3,315 s −3,016 (4.4%) | UB 1,510 s −3,009 (4.7%), 1,805 s −3,028 (3.9%) |
| S = 20 지리 1 {9:200;10:300;15:200} (resp) | 206 s 위반 발견 (−3,411.29) | 198 s 위반 발견 (−3,437.55 > 목표 −3,437.59) |

- 상한은 같은 시간에 약 두 배 앞선다 (지리 5 는 기본의 3,300 s 상한에 1,600 s 에 닿음). 지리 5 는 그래도 1,800 s 에 목표 4% 위라 HUCAP 만으로는 인증이 안 된다.
- 점검: HUCAP 상한이 기본 하한보다 늘 크다 (지리 1 S = 10: −3,676.03 ≥ 정확값 −3,678.27).
- **저장소 반영 (2026-11-25, 사용자 허락):** `nz_alpha_bnb_dr` 에 `hucap = true` (기본). `nz_presolve_hU_feas` 가 hᵁ'_k = max_s max{h_k : h ∈ H, 시나리오 s 의 recourse 실행 가능} 을 LP 로 구한다 (입지 구조를 쓰지 않는 일반형, 적어도 한 시나리오에서 실행 가능해야 최적 반응이 될 수 있음).
  다섯 점 (지리 1·5, S = 10·20) 에서 스크립트 HUCAP 의 용량값과 2e-7 안에서 같고 0.1 s 이하. 저장소 기본만으로 지리 1 S = 10 재현: 인증, 노드 2,519 (스크립트 HUCAP 2,563, 기본 정의역 4,103), 루트 UB −2,724.07 (스크립트 HUCAP 과 같음). 시간 590 s 는 S = 20 실행과 CPU 를 나눠 써서 (노드당 이완 4 배).
  `nz_benders` (`bnb = :dr`)·`run_loc_tkp`·`ccgbp` 가 모두 이 기본으로 바뀐다.
- `branch_point=:alphahat` (S = 20 지리 1, resp) 도 191 s 에 위반 발견 (−3,428.74). 위반 발견은 resp 가 정하고 분기점의 영향은 작다.

### 11.7.1 oracle λᵁ 를 낮추면 (`lam_queue.sh`, 1,800 s, resp, 기본 정의역, 목표는 λᵁ = 10⁴ 마스터 값 그대로)

### 11.10 처음부터 다시 본 점검 (2026-11-25 오후)

**(1) 싼 평가기의 여유와 η 가 안 맞아 belief 가 no-good 으로 샌다 (측정으로 확인, 저장소 `nz_belief_ccg.jl` `_bccg_value!`).**
- 평가기의 E LP 는 "α 가 belief d 에서 follower 최적" 행에 여유 κ(1 + |lhs| + max|Q|), κ = 10⁻⁷ 을 둔다. follower 비용 규모가 10⁶ 이라 절대 여유는 0.11 ~ 0.12 다.
- 블록이 동률을 깨는 힘은 η·ΔC_L 이다. η = 0.1 이면 3 ~ 5 라 이 여유를 덮고, η = 10⁻⁴ 이면 0.003 ~ 0.005 라 못 덮는다.
- 그래서 E 가 돌려주는 belief 는 α 가 0.12 만큼 비최적인 쪽 (동률의 반대편) 이고, 그 belief 의 블록 (= 정확한 pessimistic 값 V_d, 블록 자체는 정확) 이 v 보다 30 ~ 47 낮다. 확보 규칙은 이것을 블록 부족으로 보고 no-good 을 넣는다.
- 지리 5 S = 10, x = {10:400} 에서 κ 를 바꾼 측정 (`slack_check.jl`, 블록 정확성 표는 `zero_belief_check.jl`):

|---|---|---|---|---|

| 10⁻⁹ | −1,544.360 | −1,549.17 | 0.0012 | −1,556.64 |
| 10⁻¹⁰ | −1,544.360 | −1,544.36 | 1.2 × 10⁻⁴ | −1,545.59 |

**(2) 닫힌 정수 노드의 하한에 증명 안 된 값이 들어간다 (작은 유효성 문제).**
`closed_lb` = max(노드 하한, mval(c), q + oracle 하한) 인데, 정수 RMP 해 c 의 mval(c) 는 노드의 정확 CG 가 다 수렴했을 때만 노드 하한이다 (CG 는 CGTOL 0.1% 나 블록 수 × tolabs 에서 멈춤). q + oracle 하한은 점 c 하나의 하한이라 노드 전체의 하한이 아니다.
Optimal 실행 중 닫힌 노드가 LB 를 정한 것은 지리 6 (v7), 8, 9, 14 이고, 지리 6 만 차이가 난다. 보고 LB −1,574.00 대 증명된 −1,574.21 이라 간격이 0.468% → 0.481% 로, 여전히 허용 안이다. v12 는 닫거나 주차하는 노드에 증명된 Farley 하한만 쓴다 (정수 노드가 모자라면 엄격한 정확 CG 를 한 번 더).

**(3) oracle 900 s 상한: 숫자보다 그 뒤 처리가 문제다.**
- 상한 자체는 유효성과 무관하다 (UB 는 어느 시점의 상한이든 유효). resp 로 위반을 찾는 데 150 ~ 510 s, S = 10 인증 211 ~ 865 s 라 한 번에 주는 몫으로는 무리가 없다.
- 결론 없이 끝나도 `certified[c] = mval(c)` 를 적어 그 점은 확인한 것으로 친다. 그다음 정수 노드가 대등한 다른 점이면 새 α-B&B 를 처음부터 연다. 11.8.1 의 4 시간 판은 mval −1,553.40 인 점 4 개에 900 s 씩 썼다.
  한 점만 인증되면 UB ≈ −1,553.4 + 여유가 되어 나머지 대등한 노드는 모두 잘리므로, 필요한 인증은 하나다.
- **LB 가 루트 정확 CG 값 (−1,557.24) 에 4,600 s 동안 고정됐다.** 노드는 RMP ≥ UB − tol 일 때만 정확 가격을 하는데, UB 가 안 내려오니 한 번도 안 했다. 그런데 목표가 τ = LB + 0.95 tol − q 라 LB 가 생기는 순간 목표가 조여진다. 1 단계 (LB 없음) 여유는 6.99 였고, 루트 정확 CG 뒤에는 3.55 였다.
  원고 Algorithm 2 는 마스터를 정확히 풀고 τ⁺ = t₀ + m (여기서 7.77) 을 쓴다.
- S = 20 상한의 수렴 (`orep_s20_g1.log`, HUCAP 없음): 참값 근처 −3,403.4 까지 거리가 972 / 1,873 / 3,375 s 에 138 / 67 / 29 로, 시간 지수 1.1 ~ 1.4 로 준다. 그래서 여유가 절반이면 인증 시간은 2 ~ 3 배다.
- **한 점에 시간을 몰아 주면 인증된다** (`logs/orep_s20_g1_tied_long.log`, 4 시간 판의 대등한 점 {10:200;11:200;15:300}, HUCAP·resp, 목표 없이 2,000 s 에 중단).

|---|---|---|---|---|---|
| oracle 상한 | −3,380.04 | −3,391.04 | **−3,399.86** | −3,401.47 | −3,402.27 |
| 열린 노드 | 294 | 153 | 160 | 189 | 273 |

  v11 의 좁은 목표 −3,399.85 를 약 1,275 s 에 넘고, v12 목표 τ⁺ = t₀ + 0.75 m = −3,397.57 은 약 1,200 s 에 넘는다. 4 시간 판은 점마다 900 s 에서 끊어 상한이 빨리 내려가기 시작하는 바로 앞에서 다른 점으로 넘어갔다 (900 s 호출들의 상한 −3,350 ~ −3,374). 하한 (벌점 incumbent) 은 −3,402.75 로, 참값은 −3,403.4 근처에서 인증된다.

### 11.11 v12: 허용오차 예산 분할 (`ccgbp_v12.jl`, 2026-11-25)

원고 Algorithm 2 는 마스터를 정확히 풀고 (값 V̲, m = tol·max(1, |V̲|)) 그 해 x̄ 에서 oracle 을 τ⁻ = t₀ + m/2, τ⁺ = t₀ + m 으로 부른다. v12 는 이것을 한 나무 B&P 에 옮긴다.

### 11.13 α-B&B: 꼭짓점 LP 범위에 상자별 쌍대 차이 범위 (DD) 를 다시 넣기 (2026-11-25 밤)

지리 5 S = 10 의 막힌 점 {4:200;7:200;12:300} 전선 (11.6 의 HUCAP 재현, 1,805 s, 열린 상자 3,755 개, incumbent −3,156.50) 을 진단했다.
스크립트는 `front_box_gap.jl`, `front_blame.jl`, `front_dd.jl`, `front_dd_lazy.jl` 이고 로그는 `logs/fbg_g5_top.log`, `fbl_g5.log`, `fdd_g5*.log`, `fddl_g5.log`, `fddc_g5.log` 다.

**(1) 상자 안 Gurobi 전역 60 s 는 판정을 못 낸다.** 벌점 Ω (λᵁ = 10⁴) 에서 벌점이 붙은 해만 찾았고, 상한도 대부분 α-B&B 상자 상한보다 약했다.

**(2) 노드 완화 해의 출처 (`front_blame.jl`, nonzero_sum/lab_blame.jl 의 loc_tkp 판).** 다시 푼 상한이 목표보다 72 ~ 118 위인 상자 6 개를 봤다.

**(3) 상자별 DD 가 상한 큰 상자를 모두 실행 불가능으로 만든다 (`front_dd.jl`).**
- 기본 판은 `range_lp = true` 라 `dd = false` 여야 한다. 그래서 L6 이후 DD 가 꺼져 있었다.

- 루트에서 전체 정의역으로 한 번 구한 DD (90 s) 는 효과가 없다. 상한이 어느 상자에서도 그대로다. 차이가 상수인 것은 상자 안에서만 성립하기 때문이다.

### 11.14 α-B&B 를 처음부터 다시 보기 (2026-11-26)

사용자 지시는 세 가지였다. 비관적으로 보지 말 것, 실험 시간을 아낄 것, 처음부터 다시 생각할 것. 그래서 저장된 지리 5 전선 (`orep_front_g5_S10_base.jls`, 열린 상자 4,041 개, incumbent −3,156.50, 목표 −3,151.60) 에서 몇 분짜리 실험실만 돌렸다. 스크립트는 모두 스레드 1 개이고, 로그는 `logs/` 에 있다.

**(1) 상한을 만드는 오차 (front_blame 기록을 다시 읽음).**
- follower 블록은 쌍대 쪽이 선형이다. 그래서 ζF = α·d 만 정확하면 강쌍대 행이 α̂ 의 최적성을 정확히 강제한다.
- 전선 상자의 ζF 위반은 합 1.8 로 작다. 그런데 약정 한 단위의 값이 최대 p = 800 이라 follower recourse 이익 Σ(cȳ − d̂Q) 가 250 ~ 1,050 부푼다. 그만큼 최적이 아닌 α̂ 가 통과한다.
- ζF 의 McCormick·RLT 오차는 (α 폭)·(d 폭) 에 비례한다. α-B&B 는 d 를 나누지 않으므로 d 폭 (볼 상자 ±ε̃/√S = [0.037, 0.163]) 은 끝까지 그대로다.

**(2) d 를 나누기 (`front_dsplit.jl`, `logs/fds_g5.log`): 안 씀.**
- d 를 LP 해 d̂ 에 고정하면 6 개 상자가 모두 죽는다. 이것은 제한이라 상한이 아니다.
- 위반이 큰 시나리오 둘을 나눈 자식 4 개의 상한 감소는 3 ~ 15 다. 같은 수의 α 자식은 10 ~ 116 이고, 두 상자는 자식이 모두 죽는다.
- d 가 10 차원이라 몇 개만 나눠서는 오차가 거의 줄지 않는다.

**(3) 분기 좌표 (`front_strong.jl`, `logs/fst_g5.log`): 규칙은 거의 최선.** 상자 12 개에서 자식 상한 최댓값 − incumbent 의 중앙값은 다음과 같다.
